## Установка

Установка на Linux выполняется одной командой:
```shell
bash <(curl -s https://gameap.com/install.sh)
```

В процессе установки будет предложено ввести некоторые данные

### Хост

Укажите домен или IP адрес, по которому будет доступна панель.

В случае IP адреса, должен быть указан адрес, который назначен сетевому интерфейсу на VDS.
Если ваша сеть использует NAT, то не указывайте внешний IP, 
а указывайте внутренний, затем сконфигурируйте перенаправление портов.

Домен может быть указан любой, но не забудьте настроить DNS.

Пример корректных значений:
* 10.182.104.8
* 10.182.104.8:2080
* example.com
* http://example.com

### База данных

База данных, где будут храниться данные: пользователи, сведения о серверах и тд.
Можно использовать [PostgreSQL](https://www.postgresql.org/),
[MySQL](https://www.mysql.com/) и [SQLite](https://www.sqlite.org/).

В большинстве случаев рекомендуется использовать PostgreSQL.
Если нагрузка на ваш сервер планируется небольшой и вы не планируете использовать более 10 игровых серверов,
то можете использовать SQLite.

На некоторых дистрибутивах может быть установлена [MariaDB](https://mariadb.org/).

## Завершение установки

В конце установки будут отображены данные для доступа к панели.
Не забудьте сохранить эти данные, чтобы иметь доступ к панели.

## Дополнительные параметры установки

### Develop версия

Версию, находящуюся в разработке, можно установить, передав установщику дополнительные флаги
`--github --branch=develop`; `--develop` — сокращение для `--branch=develop`, его указывают
вместе с `--github`. Установка в этом случае занимает заметно больше времени, поскольку панель
собирается из исходников.

```shell
bash <(curl -s https://gameap.com/install.sh) \
  --github \
  --branch=develop
```

Для сборки из исходников нужны `git`, Node.js 24 и Go. GameAP 4.5.0 собирается с **Go 1.27**, а
gameapctl устанавливает Go 1.26.1; сборка всё равно проходит, потому что инструментарий Go сам
скачивает нужную версию, — поэтому помимо `github.com` машине нужен доступ к зеркалу модулей Go
(`proxy.golang.org`). На хостах `arm64` установите Go заранее самостоятельно: gameapctl скачивает
архив Go для `amd64` независимо от архитектуры.

Такая установка перестаёт быть простой заменой бинарника. gameapctl запоминает, что панель
собрана из GitHub и из какой ветки, поэтому каждый последующий `gameapctl panel upgrade` без
флагов пересобирает её из той же ветки и требует тех же инструментов. Чтобы вернуться к
релизным сборкам, выполните `gameapctl panel upgrade --version=<тег>`. В продакшене используйте
релизную сборку.

### Установка без вопросов

Данный вид установки позволяет установить панель не вводя никаких данных во время установки.
Укажите флаги, и установщику не потребуется получать от вас дополнительных данных.

```shell
bash <(curl -s https://gameap.com/install.sh) \
  --non-interactive \
  --host=127.0.0.1 \
  --port=8025 \
  --database=sqlite
```

Основные флаги:

| Флаг                  | Назначение                                                                                          |
|-----------------------|-----------------------------------------------------------------------------------------------------|
| `--non-interactive`   | Не задавать вопросов                                                                                |
| `--host`              | Адрес, по которому будет доступна панель                                                            |
| `--port`              | Порт панели: по умолчанию `80`, с `--scope=user` — `8025`                                           |
| `--grpc-port`         | Порт gRPC для демонов, по умолчанию `31718`                                                         |
| `--database`          | `sqlite`, `mysql` или `postgres`                                                                    |
| `--database-host`     | Хост базы данных                                                                                    |
| `--database-port`     | Порт базы данных                                                                                    |
| `--database-name`     | Имя базы данных                                                                                     |
| `--database-username` | Пользователь базы данных                                                                            |
| `--database-password` | Пароль пользователя базы данных                                                                     |
| `--with-daemon`       | Установить заодно GameAP Daemon                                                                     |
| `--version`           | Конкретная версия панели, тегом: `4.5.0`                                                            |
| `--scope`             | `system` (по умолчанию, нужен root) или `user` — см. [Установка без root](#установка-без-root)      |
| `--github`            | Собрать панель из исходников вместо установки релиза                                                |
| `--develop`           | Сокращение для `--branch=develop`; указывается с `--github` — см. [Develop версия](#develop-версия) |
| `--branch`            | Ветка репозитория для `--github`. В `--help` не показывается                                        |

Для SQLite параметры подключения не нужны — файл базы создаётся автоматически.

Если порт по умолчанию занят, установщик берёт первый свободный из `8025`, `8026` и далее
(проверяется до десяти портов) и сообщает, какой выбрал. Порт, заданный явно — через `--port` или
как `--host=example.com:8080`, — никогда не подменяется: установщик предупредит, подскажет
свободный порт для повторного запуска и спросит, продолжать ли с запрошенным. С
`--non-interactive` установка на этом предупреждении прерывается, если не передан
`--skip-warnings`.

`--version` нельзя сочетать с `--github`, `--branch` и `--develop`.

> Флаги `--path` и `--web-server` остались от GameAP 3 и при установке GameAP 4 не действуют:
> панель — один исполняемый файл со встроенным веб-интерфейсом, отдельный веб-сервер ей не нужен.

### Полная установка

Чтобы помимо самой панели установить GameAP Daemon добавьте флаг `--with-daemon`.

Этот способ рекомендуется, если вы планируете размещать панель и игровые серверы на одной VDS.

```Shell
bash <(curl -s https://gameap.com/install.sh) --with-daemon
```

### Установка без root

С флагом `--scope=user` панель — а с `--with-daemon` и демон — устанавливается без root в домашний
каталог текущего пользователя и работает как пользовательский юнит systemd. Только для Linux.

```shell
gameapctl panel install --scope=user --host=example.com --database=sqlite
```

Область установки запоминается, поэтому остальные команды — `start`, `stop`, `restart`, `status`,
`upgrade`, `uninstall`, `change-password`, `https` — подхватывают её сами. Если файл состояния в
`~/.gameapctl` потерян, передайте `--scope=user` явно.

| Что          | Системная установка                  | Пользовательская установка              |
|--------------|--------------------------------------|-----------------------------------------|
| `config.env` | `/etc/gameap/config.env`             | `~/.config/gameap/config.env`           |
| Данные       | `/var/lib/gameap`                    | `~/.local/share/gameap`                 |
| Бинарник     | `/usr/bin/gameap`                    | `~/.local/bin/gameap`                   |
| Юнит systemd | `/etc/systemd/system/gameap.service` | `~/.config/systemd/user/gameap.service` |

В неинтерактивных оболочках `~/.local/bin` часто отсутствует в `PATH`. Службе это не мешает — в
юните абсолютные пути, — но чтобы запускать `gameap` по имени, добавьте его:
`export PATH="$HOME/.local/bin:$PATH"`.

Что требуется:

* Linux с systemd.
* Настоящая сессия входа, чтобы `systemctl --user` достучался до пользовательской шины:
  подключайтесь через `ssh user@host` или `machinectl shell user@`, а не через `su` или `sudo -u`.
* Lingering, чтобы службы переживали выход из сессии и запускались при загрузке. Установщик
  пытается включить его сам и предупреждает, если ему отказано. Проверить:
  `loginctl show-user $USER --property=Linger`; если выводится `Linger=no`, выполните
  `sudo loginctl enable-linger $USER`.

Ограничения:

* Порты ниже 1024 непривилегированному процессу обычно недоступны, поэтому панель по умолчанию
  использует `8025`, а HTTPS — `8443`. Установщик проверяет порт, а не отвергает всё ниже 1024,
  так что низкие порты работают там, где администратор понизил `net.ipv4.ip_unprivileged_port_start`.
* Сервер базы данных не устанавливается — **по умолчанию SQLite**. `--database=mysql` и
  `--database=postgres` принимаются только для уже работающего сервера, который описывается
  флагами `--database-host`, `--database-name`, `--database-username` и `--database-password`
  (плюс `--database-port`, если порт нестандартный).
* Инструменты сборки не устанавливаются. Для `--github` нужны уже установленные `git`, `go` и `npm`.
* Подтверждение Let's Encrypt по `http-01` недоступно — ему нужен порт 80. Используйте `dns-01`;
  см. [HTTPS и сертификаты](/ru/https.html).
* Системный пользователь и группа `gameap` не создаются: всё работает от текущего пользователя.
