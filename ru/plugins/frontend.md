## Как встраивается фронтенд

Плагин может содержать интерфейс — Vue 3-компоненты, собранные в JS-бандл и CSS и встроенные в тот же файл `.wasm`. Панель отдаёт склейку фронтенд-бандлов всех загруженных плагинов по адресам `/plugins.js` и `/plugins.css` (только для аутентифицированных пользователей). Загрузчик панели импортирует этот код как модуль и регистрирует каждый экспортированный объект `PluginDefinition`.

> **Граница доверия.** WASM-часть плагина выполняется в песочнице, а фронтенд — нет. Это обычный
> JavaScript, работающий в том же источнике, что и панель: ему доступны страница целиком и
> `window.axios` с правами текущего пользователя. Плагин с фронтендом фактически получает те же
> возможности, что и сам интерфейс панели, поэтому устанавливайте только те плагины, источнику
> которых доверяете.

Фронтенд плагина работает в контексте основного SPA панели (это не iframe и не web component) и использует библиотеки панели через глобальные объекты:

| Глобальный объект       | Содержимое                                                                  |
|-------------------------|-----------------------------------------------------------------------------|
| `window.Vue`            | Vue 3                                                                       |
| `window.VueRouter`      | Vue Router                                                                  |
| `window.Pinia`          | Pinia                                                                       |
| `window.axios`          | Настроенный axios-инстанс панели (с авторизацией)                           |
| `window.NaiveUI`        | Naive UI                                                                    |
| `window.naive`          | Псевдоним `window.NaiveUI`, сохранён для отладочного окружения              |
| `window.gameapUI`       | Библиотека компонентов `@gameap/ui` (собственные UI-компоненты панели)      |
| `window.__gameap_vue_h` | `Vue.h`, сохранён для обратной совместимости с плагинами на render-функциях |

## Манифест `PluginDefinition`

Отдельного файла-манифеста нет: манифестом фронтенда служит экспортируемый из бандла объект `PluginDefinition`:

| Поле           | Обязательное | Описание                                                                    |
|----------------|--------------|-----------------------------------------------------------------------------|
| `id`           | Да           | Идентификатор плагина; должен совпадать с `id` из `PluginInfo` бэкенда      |
| `name`         | Да           | Название плагина                                                            |
| `version`      | Да           | Версия (семвер)                                                             |
| `apiVersion`   | Да           | Версия фронтенд API, только `'1.0'`                                         |
| `description`  | Нет          | Описание                                                                    |
| `author`       | Нет          | Автор                                                                       |
| `routes`       | Нет          | Собственные страницы плагина                                                |
| `menuItems`    | Нет          | Пункты левого меню (сайдбара)                                               |
| `slots`        | Нет          | Компоненты во встроенных слотах панели                                      |
| `homeButtons`  | Нет          | Кнопки на главной странице                                                  |
| `fileEditors`  | Нет          | Редакторы файлов для файлового менеджера                                    |
| `translations` | Нет          | Словари переводов по кодам языков, `{ en: {...}, ru: {...} }`               |
| `onInit`       | Нет          | Хук инициализации (синхронный или возвращающий `Promise`), вызывается при регистрации плагина |
| `onDestroy`    | Нет          | Хук очистки с той же сигнатурой; объявлен на будущее                        |

* `onInit` может быть асинхронным: загрузчик дожидается его завершения при регистрации. Исключение внутри хука записывается в консоль браузера (`Plugin <id> onInit failed:`) и не прерывает регистрацию.
* `onDestroy` объявлен в SDK, но панель в 4.5.0 его не вызывает — не полагайтесь на него для освобождения ресурсов.
* Определение с `apiVersion`, отличным от `'1.0'`, отклоняется с ошибкой `Unsupported API version`; ошибка записывается в консоль, плагин не регистрируется.

## Точки интеграции

| Механизм      | Где появляется                                                                                    |
|---------------|---------------------------------------------------------------------------------------------------|
| `routes`      | Собственные страницы с адресами `/plugins/{id}/...`                                               |
| `menuItems`   | Пункты сайдбара (секции `servers`, `admin`, `custom`)                                             |
| `homeButtons` | Кнопки на главной странице, рядом с **Серверы** и **Ноды**                                        |
| `slots`       | Компоненты в 20 встроенных слотах панели (см. ниже)                                               |
| `fileEditors` | Файловый менеджер: контекстное меню и действие по двойному щелчку — открытие файла в редакторе плагина |

### Регистрация компонента слота

Каждый элемент `slots[slotName]` — объект `PluginSlotComponent`:

| Поле              | Описание                                                                                                      |
|-------------------|---------------------------------------------------------------------------------------------------------------|
| `component`       | Vue-компонент для отображения (обязательное)                                                                  |
| `order`           | Порядок сортировки внутри слота, по возрастанию (по умолчанию `0`)                                            |
| `label`           | Отображаемая подпись (заголовок вкладки); поддерживает `@:ключ`                                               |
| `icon`            | Имя иконки из реестра `@gameap/ui` (например `'plug'`, `'metrics'`); устаревший класс Font Awesome ещё отображается, но выводит предупреждение в консоль |
| `name`            | Уникальное имя внутри слота; для `server-tabs` входит в ключ вкладки `plugin-{pluginId}-{name}`               |
| `props`           | Props компонента по умолчанию. Сливаются с контекстом хоста (при совпадении ключей побеждает хост) во всех слотах, кроме `server-tabs`: этот слот передаёт только `serverId`, `server` и `pluginId`, а зарегистрированные `props` отбрасывает |
| `checkPermission` | Условие по правам, см. ниже                                                                                   |
| `checkGame`       | Условие по игре, см. ниже                                                                                     |

Регистрация в неизвестный слот ничего не делает — в консоль выводится предупреждение `Unknown slot: <name>`.

### `checkPermission` и `checkGame`

* `checkPermission: { type: 'hasServerPermissions', permissions: [...] }` — компонент отображается, только если у пользователя есть **все** перечисленные права на сервер (плагинные права имеют вид `plugin:{id}:...`, например `plugin:ezvdsxmlu6fbk:manage`).
* `checkGame: { engines?: string[], codes?: string[] }` — компонент отображается, если игра сервера совпадает хотя бы с одним перечисленным движком (сравнение с `game.engine` без учёта регистра) **или** с одним кодом (точное совпадение с `game.code`). Пустой `checkGame` подходит любой игре; пока данные об игре сервера не загружены, компонент не отображается. Пример: `checkGame: { engines: ['GoldSource'], codes: ['cstrike', 'valve'] }`.
* Условия независимы; если заданы оба, должны выполняться оба.
* Невыполненное условие означает «не отображается», а не «недоступно».

> Эти условия проверяют ровно четыре слота — `server-tabs`, `server-control-buttons`,
> `server-control-blocks` и `servers-list-actions` — и, только `checkPermission`, редакторы файлов
> (игры они ограничивают правилами соответствия `gameCode` / `gameName`).
> Все остальные слоты отображают каждый зарегистрированный компонент безусловно, поэтому никогда не
> прячьте этими полями чувствительное содержимое, например в `admin-user-info` или слотах
> `admin-*-edit-blocks`.

### Блоки на страницах редактирования

Объект `form`, передаваемый в слоты `admin-*-edit-blocks`, — это снимок **несохранённой** формы, и секретов в нём никогда нет. Панель не сохраняет данные плагина вместе с формой — плагин хранит своё состояние через собственный API.

| Слот                       | Снимок `form`                                                                                                    |
|----------------------------|------------------------------------------------------------------------------------------------------------------|
| `admin-user-edit-blocks`   | `login`, `name`, `email`, `roles`, `servers` (`{ id, name }[]`); полей пароля нет никогда                        |
| `admin-node-edit-blocks`   | `name`, `enabled`, `os`, `location`, `provider`, `workPath`, `steamcmdPath`, `ip`; учётные данные демона, сертификаты и скрипты управления не передаются никогда |
| `admin-server-edit-blocks` | Разрешённый набор полей формы: `name`, `enabled`, `blocked`, `ip`, `serverPort`, `queryPort`, `rconPort`, `dir`, `user`, `startCommand`, `nodeId`, `game`, `gameMod`, `metadata` — пароля RCON нет никогда; `server` — разрешённый набор полей сохранённой записи (`id`, `uuid`, `uuid_short`, `name`, `enabled`, `installed`, `blocked`, `online`, `ds_id`, `game_id`, `game_mod_id`), тоже без пароля RCON |
| `admin-game-edit-blocks`   | Вся форма                                                                                                        |
| `admin-mod-edit-blocks`    | Вся форма                                                                                                        |

### Правила разметки и особенности слотов

* Компоненты `profile-info-rows` и `admin-user-info-rows` отображаются непосредственно внутри `<tbody>`: корневым элементом **должен** быть `<tr>` с двумя ячейками `<td>`, иначе разметка таблицы будет некорректной.
* Блочные слоты отображают компоненты как есть, без обёртки. Плагин, который хочет выглядеть как встроенный раздел, сам рисует `GCard` / `n-card`.
* `servers-list-actions` ничего не отображает для отключённых и заблокированных серверов (колонка команд для них пуста); компоненты создаются через `h()`, а не через `PluginSlot`, условия проверяются для каждой строки.
* `sidebar-sections` отображается в том варианте сайдбара, который сейчас на экране: свёрнутом (`minimized: true`, только иконки) или развёрнутом (`minimized: false`). Это две разные ветки разметки, поэтому при сворачивании и разворачивании сайдбара компонент уничтожается и создаётся заново — всё его состояние теряется. Сам сайдбар не отображается на экранах шириной меньше брейкпоинта `sm`. Для обычных навигационных ссылок предпочтительнее `menuItems`.
* `navbar-items` находится в панели высотой 4rem, общей с выпадающими меню справки и профиля — делайте элементы компактными.
* `admin-pages` отображается только администраторам и только на путях `/admin/*`; `global-banners` — на каждой странице для всех пользователей.

### Маршруты и пункты меню

`PluginRoute` содержит `path`, `name`, `component` и необязательный `meta`:

* `path` задаётся относительно `/plugins/{pluginId}/` и должен начинаться с `/` (панель склеивает адрес как `/plugins/{pluginId}{path}`);
* `name` получает префикс `plugin.{pluginId}.`, поэтому `route: { name: 'index' }` в пункте меню или кнопке на главной разрешается в `plugin.my-plugin.index`; маршрут без `name` становится `plugin.{pluginId}.index`;
* `meta` принимает `title` (панель ставит его заголовком документа), `requiresAuth` (по умолчанию `true`; маршрутный хук панели в любом случае требует аутентификации на всех негостевых маршрутах), `requiresAdmin` и произвольные ключи. На `requiresAdmin` этот хук в 4.5.0 не реагирует — страница только для администраторов должна сама проверять `useIsAdmin()`;
* `children` объявлен в типе, но панель регистрирует только маршрут верхнего уровня, а вложенные отбрасывает — объявляйте каждую страницу отдельным маршрутом.

`PluginMenuItem` содержит `section` (`'servers'`, `'admin'` или `'custom'`; неизвестная секция попадает в `custom`), `icon` (имя из реестра, по умолчанию `'puzzle-piece'`), `text` (поддерживает `@:ключ`), `route` (`{ name }` или `{ path }`, нормализуется так же, как у маршрутов) и `order` (по умолчанию `100`). Поле `adminOnly` объявлено в типе, но в 4.5.0 **не** учитывается — размещайте пункты только для администраторов в `section: 'admin'`, которая отображается только им.

### Кнопки на главной

`PluginHomeButton` содержит:

| Поле        | Описание                                                                                                          |
|-------------|-------------------------------------------------------------------------------------------------------------------|
| `name`      | Подпись кнопки (обязательное); поддерживает `@:ключ`                                                              |
| `icon`      | Имя иконки из реестра `@gameap/ui`, например `'metrics'`; если не задано, панель подставляет `'puzzle-piece'`. Имя, неизвестное реестру, отображается как обычный `<i class="...">` |
| `component` | Собственный Vue-компонент вместо стандартной кнопки; получает в props нормализованный `route` и `pluginId` |
| `route`     | `{ name }` или `{ path }`, нормализуется как у пунктов меню; по умолчанию — индексный маршрут плагина `plugin.{pluginId}.index` |
| `order`     | Порядок сортировки (меньше — раньше)                                                                              |

Того же результата можно добиться, зарегистрировав компонент напрямую в слот `home-buttons`.

## Редакторы файлов

Плагин регистрирует редакторы файлов через `fileEditors: PluginFileEditor[]`. Редактор появляется в контекстном меню файлового менеджера и, если не ограничен контекстным меню, становится действием по двойному щелчку для подходящих файлов.

| Поле              | Обязательное | Описание                                                                                          |
|-------------------|--------------|---------------------------------------------------------------------------------------------------|
| `id`              | Да           | Уникальный идентификатор внутри плагина                                                           |
| `name`            | Да           | Отображаемое имя — заголовок окна и подпись пункта меню по умолчанию `Edit with <name>`; поддерживает `@:ключ` |
| `component`       | Да           | Vue-компонент редактора                                                                           |
| `match`           | Да           | Правила соответствия (см. ниже)                                                                   |
| `contentType`     | Нет          | `'text'` (по умолчанию), `'binary'` или `'none'`                                                  |
| `readOnly`        | Нет          | Редактор только для чтения: в окне нет кнопки сохранения                                          |
| `icon`            | Нет          | Имя иконки из реестра `@gameap/ui`, например `'file-archive'`                                     |
| `contextMenuOnly` | Нет          | Предлагать редактор только в контекстном меню, никогда — по двойному щелчку. **Обязательно** для редактора с `allFiles`, иначе он перехватит просмотр всех изображений, видео, PDF и текста |
| `menuLabel`       | Нет          | Подпись пункта контекстного меню вместо `Edit with <name>`; поддерживает `@:ключ`                 |
| `menuGroup`       | Нет          | В какой блок контекстного меню попадает пункт: `'top'` (по умолчанию), `'open'`, `'modify'`, `'danger'` или `'info'` |
| `checkPermission` | Нет          | То же условие `hasServerPermissions`, что и у слотов; при невыполнении пункт скрывается            |
| `width`           | Нет          | Ширина окна как CSS-длина; по умолчанию `1000px`, `max-width` не задаётся — используйте значение относительно окна браузера, например `'min(1400px, 95vw)'` |
| `hideFooter`      | Нет          | Убрать подвал окна; редактор рисует действия сам, закрытие остаётся на крестике заголовка и Escape |
| `keepOpenOnSave`  | Нет          | Не закрывать окно после успешного сохранения                                                      |

### Правила соответствия и специфичность

В `match` можно сочетать `allFiles`, `fileName` (точное совпадение), `pathContains`, `fullPath` (точное совпадение), `extensions` (массив, без учёта регистра), `fileNameRegexp`, `gameCode` и `gameName`. Все указанные правила должны выполняться. Если файлу подходит несколько редакторов, все они перечисляются в контекстном меню, а самый специфичный помечается `(default)` и открывается по двойному щелчку. Специфичность: `fullPath` > `pathContains` > `fileName` > `fileNameRegexp` > `extensions` > `allFiles`; `gameCode` и `gameName` добавляют к оценке. Редактор с `contextMenuOnly: true` никогда не становится редактором по умолчанию.

### Ограничение размера и `contentType: 'none'`

Окно загружает файл до монтирования редактора, поэтому файлы больше 1 МБ (1 048 576 байт) обычными плагинными редакторами не открываются — пункт контекстного меню остаётся видимым, но недоступным. Редактор с `contentType: 'none'` не получает prop `content` вовсе, и ограничение на него не действует: он открывается для файлов любого размера и сам решает, что читать, опираясь на `fileSize` и `fileMtime` из листинга каталога. Сохранение для такого редактора тоже работает.

### Куда попадает пункт в контекстном меню

| `menuGroup` | Что содержит блок                                                        | Куда попадает пункт             |
|-------------|--------------------------------------------------------------------------|---------------------------------|
| `top`       | Ничего из файлового менеджера — отдельный блок над остальными            | в порядке плагинов              |
| `open`      | Открыть, Воспроизвести, Просмотр, Редактировать, Выбрать, Скачать, Скачать ZIP, Архивировать, Разархивировать | после собственных пунктов блока |
| `modify`    | Копировать, Вырезать, Переименовать, Права доступа, Вставить             | после собственных пунктов блока |
| `danger`    | Удалить                                                                  | после собственных пунктов блока |
| `info`      | Контрольные суммы, Свойства                                              | **перед** собственными пунктами блока, чтобы «Свойства» оставались последними |

Неизвестное значение `menuGroup` попадает в `top`.

### Компонент редактора

Компонент получает props `FileEditorProps`:

| Prop        | Описание                                                                                 |
|-------------|------------------------------------------------------------------------------------------|
| `content`   | Содержимое файла — строка для `text`, `ArrayBuffer` для `binary`; для `none` отсутствует |
| `filePath`  | Полный путь к файлу                                                                      |
| `fileName`  | Имя файла с расширением                                                                  |
| `extension` | Расширение без точки                                                                     |
| `gameCode`  | Код игры сервера, если доступен                                                          |
| `gameName`  | Название игры сервера, если доступно                                                     |
| `fileSize`  | Размер в байтах, как сообщил листинг каталога                                            |
| `fileMtime` | Время изменения в секундах Unix, как сообщил листинг каталога                            |
| `disk`      | Диск файлового менеджера, на котором находится файл                                      |
| `pluginId`  | Плагин, зарегистрировавший редактор                                                      |

Сервер, которому принадлежит файл, намеренно не передаётся в props — получайте его через `useServerId()` / `useServer()` из SDK (оба бросают исключение вне контекста плагина).

Компонент эмитит `save` (полезная нагрузка — новое содержимое, строка или `ArrayBuffer`) и `close`; запись файла на сервер выполняет сама панель. Кнопка сохранения в подвале окна вызывает у компонента открытый метод `save()`, поэтому редактор должен объявить `defineExpose({ save })` и эмитить `save` из него. После успешной записи панель вызывает открытый метод редактора `onSaved()`, если он есть, и, если не задан `keepOpenOnSave`, закрывает окно.

Окно ограничивает высоту тела редактора переменной `--gameap-plugin-editor-height` (`calc(100vh - 250px)` в 4.5.0) и прокручивает всё, что выше; поля `height` нет. Редактор с собственной прокруткой должен вычислять её высоту от этой переменной, сохраняя запасное значение для старых панелей, иначе в окне появятся две полосы прокрутки, а кнопки редактора уйдут за нижний край:

```css
.my-editor-pane {
    height: calc(var(--gameap-plugin-editor-height, calc(100vh - 250px)) - 10rem);
    overflow: auto;
}
```

## Переводы

Переводы задаются словарями `translations` по кодам языков, например `{ en: {...}, ru: {...} }`; допустим любой код — сама панель поставляется с `de`, `en`, `es` и `ru`. Порядок поиска: текущий язык интерфейса → `en` → сам ключ.

* `trans(key, params)` подставляет плейсхолдеры `:имя`: `trans('greeting', { name: 'World' })` для строки `'Hello, :name!'`.
* `usePluginTrans()` предназначен для страниц-маршрутов плагина, где контекст переводов предоставляется автоматически.
* `providePluginTrans(props.pluginId)` нужно вызвать в корневом компоненте слота (вкладки, виджета, блока); его дочерние компоненты затем могут использовать `usePluginTrans()`.
* Ссылки вида `@:ключ` поддерживаются в `label` (слоты), `text` (пункты меню), `name` (кнопки на главной), а также в `name` и `menuLabel` редактора файлов. Если у плагина нет такого ключа, панель ищет его в собственной таблице переводов.

## Доступ к API

Фронтенд плагина использует `window.axios` — тот же инстанс, что и панель, с авторизацией текущего пользователя. Через него доступны:

* API панели — например, отправка RCON-команды `POST /api/servers/{id}/rcon` или работа с файлами через `/api/file-manager/...`;
* бэкенд самого плагина по адресам `/api/plugins/{id}/...` (HTTP-маршруты, зарегистрированные WASM-частью).

## SDK `@gameap/plugin-sdk`

npm-пакет `@gameap/plugin-sdk` (версия `0.3.3` в репозитории панели на 4.5.0; peer-зависимости `vue ^3.5` и `@gameap/ui ^1.3`) предоставляет:

* TypeScript-типы: `PluginDefinition`, `PluginRoute`, `PluginMenuItem`, `PluginSlotComponent`, `PluginHomeButton`, `PluginFileEditor`, `SlotName`, `PluginContext`, `PluginRouteInfo`, `ServerData`, `UserData`, `PluginI18nContext`; перечисленные выше интерфейсы props слотов, а также `UserEditFormData` и `AdminServerSavedData`; типы редакторов `EditorContentType`, `EditorMenuGroup`, `EditorMatchRules`, `FileEditorProps`;
* хуки контекста: `usePluginContext`, `useServer`, `useServerId`, `useServerAbilities`, `useCurrentUser`, `useIsAdmin`, `useIsAuthenticated`, `usePluginRoute`, `usePluginId`;
* хуки переводов: `usePluginTrans`, `providePluginTrans`;
* реэкспорт вспомогательных функций Vue: `defineComponent`, `ref`, `computed`, `watch`, `onMounted`, `onUnmounted`;
* UI-компоненты панели (реэкспорт из `@gameap/ui`): `GBreadcrumbs`, `GCard`, `GDataTable`, `GDeletableList`, `GDivider`, `GEmpty`, `GGameIcon`, `GIcon`, `GInput`, `GMenu`, `GMenuButton`, `GMenuItem`, `GMenuItems`, `GModal`, `GStatusBadge`, `GSwitch`, `GTable`, `Loading`, `Progressbar`, а также функции реестра иконок `registerIcons`, `iconRegistry`, `getIcon`, `hasIcon`, `defaultIconMap`;
* `createPluginConfig` (импортируется из `@gameap/plugin-sdk/vite`) — готовую конфигурацию Vite: сборка в lib-режиме (ES-модуль `plugin.js`), внешние зависимости `vue`, `vue-router`, `pinia`, `axios` и `@gameap/ui` переписываются на перечисленные выше глобальные объекты (`@gameap/ui` → `window.gameapUI`). Собственный vite-конфиг нужен плагину, только если он импортирует `naive-ui` напрямую — тогда вынесите `naive-ui` во внешние зависимости с привязкой к `window.NaiveUI` (образец — `frontend/vite.config.js` в [plugin-hex-editor](https://github.com/gameap/plugin-hex-editor)).

## Темизация

Цвета панели — CSS-переменные с префиксом `--gameap-`, определённые в `/theme.css` (файл `theme.css` из `@gameap/ui`, отдаётся как есть под стабильным именем). Таблица переменных — в README пакета `@gameap/ui` (раздел «Theming»).

Порядок загрузки: `/theme.css` (`<link>` в `<head>` документа) → CSS панели (`main-*.css`) → CSS плагинов (`<style id="gameap-plugin-styles">`, вставляется до монтирования приложения) → ленивые чанки маршрутов, например файловый менеджер, которые загружаются при открытии своего маршрута. Поэтому переопределение переменной `--gameap-*` побеждает всегда, а переопределение селектора панели ненадёжно — загруженный позже чанк перекрывает его при равной специфичности. **Переопределяйте переменные, а не селекторы.**

Поставляйте обычный CSS в бандле плагина; значения для тёмной темы нужно объявлять под `html.dark` (панель переключает класс `dark` на `<html>`), объявление в `:root` проигрывает собственным правилам `html.dark` панели:

```css
:root {
    --gameap-primary: #e11d48;
    --gameap-primary-hover: #be123c;
}

html.dark {
    --gameap-surface: #1e1b4b;
}
```

Ограничения:

* `/plugins.css` отдаётся только после аутентификации, поэтому темы плагинов не действуют на экране входа.
* Компоненты Naive UI — CSS-in-JS: панель пересобирает их тему из переменных при загрузке и при каждом переключении светлой/тёмной темы, но только для тех переменных, которые она сопоставляет, — `--gameap-{primary,success,warning,danger}` и их варианты `-hover`, `--gameap-table-header`, `--gameap-surface-overlay`, `--gameap-surface-raised`, `--gameap-surface-hover`, `--gameap-text-muted`, `--gameap-tab-accent`.

В шаблонах плагина предпочитайте гарантированно доступные семантические утилитарные классы (`bg-surface`, `text-muted`, `bg-primary`, `text-danger`, `border-strong` и другие из README `@gameap/ui`) — они следуют активной теме и не требуют вариантов `dark:`. В CSS плагина используйте `var(--gameap-*)` напрямую. Прочие классы Tailwind существуют, только если их использует разметка самой панели, поэтому не полагайтесь на произвольные утилиты.

## Сборка фронтенда

```bash
npm run build   # → dist/plugin.js (+ CSS-файл)
```

Собранные `plugin.js` и CSS встраиваются в `.wasm` плагина: для Rust — скриптом `build.rs` с копированием в `OUT_DIR` и подключением через `include_bytes!` (см. [Разработка плагинов](/ru/plugins/development.html)), для AssemblyScript — скриптом кодогенерации (образец — `scripts/embed-frontend.mjs` в plugin-minecraft-modrinth).

## Локальная отладка

Пакет `@gameap/debug` запускает отладочное окружение с реальным фронтендом панели и моками API (MSW):

```bash
PLUGINS_PATH=./dist npx @gameap/debug
```

Окружение открывается на `http://localhost:5174`. Плавающая debug-панель позволяет переключать тип пользователя (администратор / обычный пользователь / гость), задержку сети и локаль. Плагин должен быть предварительно собран (`npm run build`).

## Пример `PluginDefinition`

Вкладка на странице игрового сервера, видимая только для игр на GoldSource и только пользователям с правом плагина, кнопка в ряду управления сервером и редактор-инспектор файлов только для контекстного меню, который сам загружает содержимое (по образцу plugin-goldsrc-addons):

```ts
export const myPlugin: PluginDefinition = {
    id: 'myplugin2j7d',
    name: 'My Plugin',
    version: '0.1.0',
    apiVersion: '1.0',
    description: 'My first GameAP plugin',
    author: 'Me',
    translations: {
        en: { tab_label: 'My Plugin', versions_title: 'File versions', versions_menu: 'Show versions' },
        ru: { tab_label: 'Мой плагин', versions_title: 'Версии файла', versions_menu: 'Показать версии' },
    },
    slots: {
        'server-tabs': [
            {
                component: MyTab,
                order: 100,
                label: '@:tab_label',
                icon: 'plug',
                name: 'my-tab',
                checkPermission: {
                    type: 'hasServerPermissions',
                    permissions: ['plugin:myplugin2j7d:manage'],
                },
                checkGame: {
                    engines: ['GoldSource'],
                    codes: ['cstrike', 'valve'],
                },
            },
        ],
        'server-control-buttons': [
            {
                component: BackupButton,
                order: 10,
                checkPermission: {
                    type: 'hasServerPermissions',
                    permissions: ['plugin:myplugin2j7d:manage'],
                },
            },
        ],
    },
    fileEditors: [
        {
            id: 'file-versions',
            name: '@:versions_title',
            menuLabel: '@:versions_menu',
            menuGroup: 'info',
            component: FileVersions,
            match: { allFiles: true },
            contentType: 'none',
            contextMenuOnly: true,
            readOnly: true,
            checkPermission: {
                type: 'hasServerPermissions',
                permissions: ['plugin:myplugin2j7d:manage'],
            },
        },
    ],
};
```
