Описание некоторых возможных ошибок и способов их устранения.

## С чего начать

Сначала проверьте версии — многие проблемы уже исправлены в новых релизах:

* `gameap version` на сервере с панелью выводит `GameAP <версия>` и `Build date: …`;
* `gameap-daemon version` на выделенном сервере выводит версию демона, дату сборки, ОС
  и архитектуру;
* администратору доступен блок версий на главной странице панели: текущая версия панели,
  последние доступные релизы и число устаревших демонов. Версия конкретного демона указана
  на его карточке в разделе **Администрирование** → **Выделенные серверы**, а также в поле
  **Версия GameAP Daemon** в окне сведений, которое открывается щелчком по карточке.

Как обновиться — на странице [Обновление](/ru/upgrade.html).

Почти по любой проблеме с игровым сервером подробности есть в двух местах.

**Задания в панели.** **Администрирование** → **Выделенные серверы** → кнопка **Задания GDaemon**;
откройте последнее задание — там результат выполнения команды и вывод ошибки. Та же кнопка в окне
сведений о выделенном сервере (открывается щелчком по карточке) показывает список только по этому
серверу. Адрес страницы не изменился: `/admin/gdaemon_tasks`.

**Журнал демона** на выделенном сервере:

* Linux — `/var/log/gameap-daemon/output.log`
* Windows — `C:\gameap\daemon\logs\output.log`

Если демон работает под systemd, тот же вывод доступен командой:

```shell
journalctl -u gameap-daemon -n 200 --no-pager
```

Чтобы получить больше подробностей, поставьте в конфигурации демона `log_level: debug`
и перезапустите его.

## Ошибки запуска сервера

### Статус сервера отображается неверно

Иногда сервер запускается, но в панели отображается как офлайн.
См. [Ошибки отображения статуса сервера](#ошибки-отображения-статуса-сервера).

### Не указана команда запуска игрового сервера

Ошибка возникает, когда команда запуска для игрового сервера пуста.

Перейдите на страницу администрирования игровым сервером: **Администрирование** →
**Игровые серверы** → выберите игровой сервер. Либо с главной страницы: **Список серверов** →
выберите сервер → **Управление** → **Администрирование**.

Найдите поле **Команда запуска игрового сервера** и впишите команду. Для Counter-Strike 1.6 она
будет примерно такой:

```text
./hlds_run -game cstrike +ip {ip} +port {port} +map {default_map} +maxplayers {maxplayers} +sys_ticrate {fps}
```

Подробнее — [настройка игровых серверов](/ru/gameap_configure/game_servers.html#команда-запуска).
Команду запуска по умолчанию можно задать
[в настройках модификации](/ru/gameap_configure/games.html#команды-запуска-по-умолчанию).

### Окно с информацией висит и не меняется долгое время

Обычно запуск занимает меньше 10 секунд. Если полоса состояния застыла или статус не меняется
несколько минут, проверьте, работает ли демон и подключён ли он к панели:

```shell
systemctl status gameap-daemon
```

Если демон не запущен:

```shell
systemctl start gameap-daemon
```

Если запущен, посмотрите в журнале, установлено ли соединение с панелью. Сообщения
`gRPC connection failed` и `Reconnecting to panel...` означают, что демон до панели не достучался —
см. [Демон не подключается к панели](#демон-не-подключается-к-панели).

### Server start task is already exists / Задача уже существует

Ошибка возникает, когда задача на запуск уже создана и ещё не выполнена.

Откройте список заданий: **Администрирование** → **Выделенные серверы** → **Задания GDaemon**.
Найдите задачу со статусом **ожидание**, откройте её кнопкой **Просмотр** и нажмите
**Отменить**. После этого запустите сервер ещё раз.

Если задачи регулярно зависают в ожидании, значит демон их не забирает — проверьте, работает ли он
и подключён ли к панели.

## Ошибки отображения статуса сервера

### Несоответствие времени

Проблема связана с расхождением времени на сервере с панелью и на выделенном сервере.

Настройте синхронизацию часов на обоих серверах:

```bash
timedatectl set-ntp true
timedatectl status
```

Если systemd не используется, включите службу синхронизации времени — например `chronyd`
или `ntpd`.

Отдельно проверьте часовой пояс: он на точность часов не влияет, но из-за него время
в интерфейсе может отображаться со сдвигом.

```bash
timedatectl set-timezone Europe/Moscow
```

В Debian и Ubuntu часовой пояс можно выбрать и в диалоге: `dpkg-reconfigure tzdata`.

### Демон подключён, но статус не обновляется

Демон сообщает о состоянии серверов раз в `metrics.collection_interval` (по умолчанию 5 секунд)
и присылает heartbeat раз в 30 секунд. Если данные не обновляются дольше, посмотрите в журнале
демона, не разрывается ли соединение.

## Ошибки установки серверов

Чтобы установить причину, посмотрите результат выполнения команды установки: **Администрирование** →
**Выделенные серверы** → **Задания GDaemon** → найдите задание на установку и откройте.

Частые причины:

* [Нет источника](#нет-источника)
* [Неправильно сформирован архив установки](#неправильно-сформирован-архив-установки)
* [Неправильно указан источник установки](#неправильно-указан-источник-установки)

### Нет источника

Панель не знает, откуда устанавливать игровой сервер. Способов несколько:

* через SteamCMD — в настройках игры должен быть указан Steam APP ID;
* из удалённого репозитория — должна быть указана ссылка на ZIP или TAR архив (RAR не поддерживается);
* из локального репозитория — путь к каталогу с файлами или к ZIP или TAR архиву. Файлы должны
  находиться на выделенном сервере, где работает демон.

Источник задаётся на странице **Администрирование** → **Игры** → выберите игру → **Редактировать**.

### Неправильно сформирован архив установки

Архив должен содержать файлы игрового сервера в корне. Самая частая ошибка — файлы лежат
во вложенном каталоге.

Неправильно сформированный архив для GTA: San Andreas Multiplayer:

![Неправильный архив установки: файлы игрового сервера лежат во вложенном каталоге](/images/errors/source_archive_wrong.jpg)

Правильно:

![Правильный архив установки: файлы игрового сервера лежат в корне архива](/images/errors/source_archive_right.jpg)

### Неправильно указан источник установки

Для локального репозитория проверьте, существует ли каталог на выделенном сервере, где работает
демон.

Для удалённого — проверьте, что по ссылке действительно начинается скачивание файла. Ссылки
на Яндекс Диск, Google Drive и подобные хранилища не поддерживаются: по ним отдаётся страница,
а не файл.

### Failed to install via steamcmd

Иногда SteamCMD прерывается посреди загрузки. Панель умеет работать с альтернативным загрузчиком
depot downloader — замените скрипт SteamCMD:

```shell
cd /srv/gameap/steamcmd
mv steamcmd.sh steamcmd.sh.orig
curl -O https://raw.githubusercontent.com/gameap/steamcmd-depotdownloader/main/steamcmd.sh
chmod 755 steamcmd.sh && chown gameap:gameap steamcmd.sh
```

### Требуется вход в аккаунт Steam

Часть игр нельзя скачать анонимно — нужен аккаунт с приобретённой копией. Укажите его в разделе
`steam_config` конфигурации демона, см. [GameAP Daemon](/ru/daemon/daemon.html#учётная-запись-steam).

На этом аккаунте должна быть отключена двухфакторная аутентификация, иначе демон не сможет войти.

## Ошибки GameAP Daemon

### Демон не подключается к панели

В GameAP 4 соединение устанавливает демон: он сам подключается к панели по gRPC на порт **31718**.
Панель к демону не подключается, и входящие порты на выделенном сервере для этого не нужны.

Признак в журнале демона — повторяющиеся `gRPC connection failed` и `Reconnecting to panel...`.

Что проверить:

1. **Доступность порта** с выделенного сервера:

   ```shell
   nc -zv panel.example.com 31718
   ```

   Если соединение не устанавливается, порт закрыт файрволом или панель слушает другой адрес.

2. **Адрес панели** в конфигурации демона — параметр `grpc.address`. Он должен указывать
   на адрес, доступный с выделенного сервера.

3. **Ошибка проверки сертификата.** Если в журнале сообщение о несовпадении имени в сертификате,
   значит демон подключается по адресу, которого нет в gRPC-сертификате панели. Задайте
   в конфигурации панели `GRPC_EXTERNAL_HOST` и перезапустите панель — сертификат перевыпускается
   автоматически, в журнале панели появится `Certificate SANs mismatch, regenerating`.
   См. [GRPC API](/ru/daemon/grpc.html#адрес-панели-для-демона).

   Начиная с 4.4.2 панель предупреждает об этом заранее. Формируя команду установки демона, она
   сверяет адрес подключения со своим сертификатом; если адрес им не покрыт, в журнал панели
   пишется `resolved gRPC connect host is not covered by the panel gRPC TLS certificate` с полем
   `grpc_host`, а `GET /api/nodes/setup` возвращает то же предупреждение в массиве `warnings`.
   gameapctl при установке демона тоже проверяет сертификат: выводит
   `WARNING: the panel gRPC certificate does not cover host "<host>"` и переключается на адрес
   той же машины, который сертификатом покрыт, а если такого нет — завершается с ошибкой.

4. **`registration failed`.** Соединение установлено, но панель отклонила регистрацию: неверный
   `ds_id` или `api_key` в конфигурации демона. Проще всего зарегистрировать демона заново.

### Не работает консоль или файловый менеджер

Если серверы запускаются и останавливаются, а консоль и файловый менеджер не работают, проблема
почти всегда в соединении с панелью: команды управления могли выполниться до разрыва, а консоль
и файлы требуют работающего потока данных.

Проверьте соединение по разделу выше, при необходимости перезапустите демона:

```shell
systemctl restart gameap-daemon
```

### Файл не загружается через файловый менеджер

Файловый менеджер всегда загружает файлы частями размером `FILES_UPLOAD_CHUNK_SIZE` (по умолчанию
8 МБ), поэтому размер файла — не причина: ограничение в 100 МБ действует только для загрузки одним
запросом через API-эндпоинт `POST /api/file-manager/{server}/upload`. На причину указывает
сообщение в панели загрузки:

| Сообщение                                                | Причина                                                                                                                                                         |
|----------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Отклонено прокси (слишком большой запрос)** — HTTP 413 | Обратный прокси отбросил часть файла (в ответе нет JSON-тела панели). Увеличьте `client_max_body_size` в nginx так, чтобы он превышал `FILES_UPLOAD_CHUNK_SIZE` |
| **Сессия истекла, повторите** — HTTP 410 или 404         | Сессия загрузки просуществовала дольше `FILES_UPLOAD_SESSION_TTL` (по умолчанию 24 часа). Начните загрузку заново                                               |
| **Несовпадение контрольной суммы** — HTTP 422            | Файл изменился на диске во время загрузки. Начните загрузку заново                                                                                              |

Переменные `FILES_UPLOAD_ALLOW_ARCHIVES` и `FILES_UPLOAD_ALLOW_BINARY` разрешают загрузку архивов
и двоичных файлов, см. [Безопасность](/ru/security.html). Архив, который уже лежит на выделенном
сервере, можно распаковать на месте командой **Разархивировать**, см.
[Файловый менеджер](/ru/gameap_configure/file_manager.html#архивы).

### Не работают архивация, распаковка или контрольные суммы

Архивы и контрольные суммы обрабатывает демон на выделенном сервере; для операций с архивами
нужен GameAP Daemon 4.1.0 или новее.

| Симптом                                                | Причина                                                                                                                                                                                                                          |
|--------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `node does not support archive operations` — HTTP 502  | Демон на этом выделенном сервере старше 4.1.0. Обновите его                                                                                                                                                                      |
| Скачивание каталога ZIP-архивом завершается HTTP 429   | Для этого игрового сервера ещё идёт другое скачивание (`FILES_ARCHIVE_CONCURRENT_PER_SERVER`, по умолчанию 2). Дождитесь его окончания                                                                                           |
| Скачивание каталога ZIP-архивом завершается HTTP 413   | Каталог превышает `FILES_ARCHIVE_MAX_BYTES` или `FILES_ARCHIVE_MAX_FILES`; те же ограничения действуют при создании и распаковке архивов                                                                                         |
| `archive is encrypted, password required`              | Архив защищён паролем; такие архивы распаковать нельзя                                                                                                                                                                           |
| Операция запускается, но ход выполнения не обновляется | Прогресс приходит по WebSocket `/api/ws/servers/{server}/file-manager/archive-operations`, который браузер не смог открыть — проверьте проксирование WebSocket на обратном прокси, см. [WebSocket и метрики](/ru/websocket.html) |

Ограничения описаны в [Справочнике config.env](/ru/config.html#архивы).

### После перезагрузки сервера демон не запускается

Включите автозапуск:

```shell
systemctl enable gameap-daemon
```

### Task complete with an error

Общая ошибка при установке, запуске, перезапуске или остановке игрового сервера. Причин может быть
много.

Откройте **Администрирование** → **Выделенные серверы** → **Задания GDaemon**, найдите последнее
задание и посмотрите подробности. Затем проверьте журнал демона.

#### No source to install game

Для игры не задан ни один источник установки. См. [Нет источника](#нет-источника).

## Ошибки входа в панель

### После обновления не пускает администратора

В GameAP 4 двухфакторная аутентификация для администраторов обязательна: через 30 дней после первого
напоминания вход перестаёт выдавать полноценную сессию. Это не блокировка учётной записи — нужно
подключить 2FA и войти заново.

Порядок действий, в том числе при утере устройства с кодами, — [Безопасность](/ru/security.html).

### Вход перестал работать после обновления до 4.5

Начиная с 4.5.0 логины и адреса e-mail хранятся в нижнем регистре, а при входе регистр не
учитывается, поэтому регистр вводимых букв значения не имеет. Ломает вход коллизия: если две учётные
записи различались только регистром, после обновления идентификатор в нижнем регистре остаётся
лишь у одной из них, а вторая войти по нему больше не может. В журнале панели при этом есть
предупреждение `Migration 022 could not fold a user identifier` с полями `column`, `user_id`
и `kept_by_user_id`. Администратору нужно задать второй учётной записи новый логин или e-mail
на странице [Пользователи, роли и права](/ru/users.html). Подробнее —
[Обновление](/ru/upgrade.html#логины-и-e-mail-приводятся-к-нижнему-регистру).

### Слишком много попыток входа

После 20 неудачных попыток с одного адреса или 5 попыток на один логин вход блокируется на 15 минут,
ответ — `429`. Ограничение снимается само по истечении времени.

### Пароль не принимается при смене

Длина пароля — от 12 до 128 байт, и он проверяется по списку скомпрометированных паролей.
См. [Безопасность](/ru/security.html).

## Блок версий на главной странице

Блок видят только администраторы; как он работает, описано на странице
[Обновление](/ru/upgrade.html#как-узнать-о-новой-версии).

Надпись **Проверка обновлений отключена** под блоком означает `UPDATE_CHECK_ENABLED=false`
в `config.env`.

Красный индикатор **Не удалось получить информацию** рядом с **GameAP Daemon** означает, что
панель не смогла сравнить версии демонов: не загрузилась сводка по выделенным серверам, неизвестен
последний релиз GameAP Daemon или неизвестна версия хотя бы одного демона — например, он офлайн.
Релиз неизвестен, если не удалось обратиться ни к одному источнику из `UPDATE_CHECK_URLS`:
проверьте исходящий HTTPS-доступ и настройки прокси на сервере с панелью. Запрос прерывается
через 15 секунд; неудачный результат кэшируется на 15 минут, удачный — на `UPDATE_CHECK_TTL`
(по умолчанию 6 часов). Переменные описаны в
[Справочнике config.env](/ru/config.html#проверка-обновлений).

## Поиск причин

Если вашей проблемы здесь нет, ищите подробности в журналах.

**Проверка работоспособности панели.** `curl http://<host>:<port>/api/health` отвечает без
аутентификации и проверяет соединение с базой данных, так что позволяет отличить неработающую панель
от проблемы с базой. Порт задаётся переменной `HTTP_PORT` (по умолчанию 8025).

**Журнал демона** — `/var/log/gameap-daemon/output.log` в Linux, `C:\gameap\daemon\logs\output.log`
в Windows. Для подробного вывода поставьте `log_level: debug` в конфигурации демона и перезапустите
его.

**Журнал панели** — вывод процесса `gameap`. Под systemd:

```shell
journalctl -u gameap -n 200 --no-pager
```

Уровень подробности задаётся переменной `LOGGER_LEVEL`, см.
[Справочник config.env](/ru/config.html).

Предупреждения при запуске панели —
`environment variable is deprecated and will be removed in a future release` и
`both the deprecated and the current environment variable are set, the deprecated one is ignored`,
каждое с полями `deprecated` и `use`, — означают, что в `config.env` остались старые имена
переменных `PLUGIN_*`. Переименуйте их, как описано на странице
[Обновление](/ru/upgrade.html#переименованные-переменные-конфигурации).

**Задания** — в панели **Администрирование** → **Выделенные серверы** → **Задания GDaemon**: там
результат выполнения каждой команды запуска, установки и перезапуска.

**Отправка журналов в поддержку.** `gameapctl send-logs` собирает журналы gameapctl, демона, панели,
веб-сервера и базы данных, состояние служб, состояние установки и сведения о системе, загружает архив
и выводит **Logs ID**, который нужно передать в поддержку. Дополнительные каталоги подключаются
флагом `--include-logs`, например `--include-logs=/var/log/nginx`; флаг можно указывать несколько раз.
