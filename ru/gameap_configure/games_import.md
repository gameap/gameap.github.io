Настройки игр и модификаций можно переносить между установками GameAP и брать из других панелей
управления. Возможность появилась в GameAP 4.1.

Всё это находится на странице **Администрирование** → **Игры**. Кнопка **Импортировать**
открывает страницу импорта с двумя вкладками: **GameAP** — собственный формат панели и
**Pelican/Pterodactyl** — egg-файлы из других панелей.

![Кнопки импорта и экспорта на странице «Игры» в администрировании](/images/ru/gameap_configure/games_import/import_button.png)

На обеих вкладках есть сворачиваемый блок **Переопределение**. Поле **Имя** заменяет название игры
из файла (*Оставьте пустым для использования оригинала*), поле **Код** — код игры (*Оставьте
пустым для автогенерации*). Через API оба эндпоинта импорта принимают те же переопределения в
query-параметрах `name` и `code`. Код — от 2 до 16 символов по шаблону `^[a-z0-9_-]+$`, имя — от
2 до 128 символов.

## Собственный формат GameAP

Формат GameAP переносит игру целиком: саму игру, все её модификации, переменные с полными
определениями (тип, варианты значений, правила проверки, переводы), команды запуска и команды
RCON. Все ключи определения переменной необязательны, поэтому файлы, созданные в старых версиях
панели, импортируются без изменений.

### Экспорт

На странице **Администрирование** → **Игры** откройте игру и нажмите **Экспорт**. Панель отдаст
файл `<код-игры>.gameap.yaml`.

Через API:

```http
GET /api/games/{code}/export
```

### Импорт

**Администрирование** → **Игры** → **Импортировать**, на вкладке **GameAP** загрузите файл и
нажмите **Импортировать**. Перед импортом панель показывает название, код, движок и число
модификаций, найденных в файле.

![Страница импорта игр с выбором YAML-файла настроек](/images/ru/gameap_configure/games_import/import_page.png)

Через API:

```http
POST /api/games/import/gameap
```

Импорт создаёт игру, если её ещё нет, и **обновляет существующую**, если игра с таким кодом уже
заведена. Модификации импортируются вместе с игрой — после загрузки панель сообщает, сколько их
импортировано; в ответе API они дополнительно перечислены в полях `mods_created` и
`mods_updated`.

Что именно происходит с уже заведёнными данными:

* **Игра сопоставляется по коду**, модификация — по имени в пределах этой игры.
* Совпавшие записи **перезаписываются** значениями из файла: команды запуска, переменные,
  команды RCON, репозитории. Прежние значения не сохраняются.
* Исключение — поле метаданных: оно сливается, а не затирается.
* Модификации, которые есть в панели, но отсутствуют в файле, **не удаляются** и остаются как
  были.

> Импорт поверх настроенной игры затирает ваши правки. Перед загрузкой файла выгрузите текущую
> игру экспортом — это единственный способ вернуть прежние настройки, если результат не устроит.

Перед записью файл проверяется:

* тело запроса — не более 1 МБ;
* `game.code` — от 2 до 16 символов по шаблону `^[a-z0-9_-]+$`;
* имена модификаций в одном файле не должны повторяться;
* определения переменных проверяются так же, как при сохранении модификации через
  `PUT /api/game_mods/{id}`.

В начале файла указана версия формата:

```yaml
schema_version: "1.0"
```

Файл с другой версией формата панель не примет. Это же поле стоит проверить, если перенос
не удался.

## Импорт из других панелей

Поддерживается импорт заготовок из:

* [Pterodactyl](https://pterodactyl.io/)
* [Pelican](https://pelican.dev/)

**Администрирование** → **Игры** → **Импортировать**, на вкладке **Pelican/Pterodactyl** загрузите
egg-файл и нажмите **Импортировать**. Принимаются JSON (Pterodactyl `PTDL_v2` и Pelican `PLCN_v3`)
и YAML (`PLCN_v3`); формат определяется по содержимому.

Через API:

```text
POST /api/games/import/pelican-egg
```

Формат egg у обеих панелей общий, поэтому файлы Pterodactyl и Pelican загружаются одинаково.

### Что создаёт импорт

* Игру с движком `pelican`. Код формируется из названия egg: нижний регистр, последовательности
  символов, кроме латинских букв и цифр, заменяются на `_`, не более 16 символов. Свой код можно
  задать в блоке **Переопределение**.
* Одну модификацию с именем **Default**, у которой заполнена только команда запуска для Linux.
  Повторный импорт egg с тем же кодом обновляет эту игру и модификацию; их метаданные сливаются с
  существующими.
* Команда запуска переводится на плейсхолдеры GameAP: `{% raw %}{{server.build.default.port}}{% endraw %}` и
  `{% raw %}{{server.build.env.PORT}}{% endraw %}` становятся `{port}`, `{% raw %}{{server.build.default.ip}}{% endraw %}` и
  `{% raw %}{{server.build.env.SERVER_IP}}{% endraw %}` — `{ip}`, любой другой `{% raw %}{{VARIABLE}}{% endraw %}` или
  `{% raw %}{{server.build.env.VARIABLE}}{% endraw %}` — `{VARIABLE}`. Команда с shell-операторами (`&&`, `||`, `;`,
  `|`, `&`, перенаправления, подстановка команд) оборачивается в `/bin/sh -c "…"`.
* Переменные egg становятся типизированными переменными модификации: `env_variable` — имя
  переменной, `default_value` — значение по умолчанию, `name` — подпись, `description` —
  описание, а переменная без признака `user_editable` становится доступной только администратору.
  Правила Laravel переводятся так: `integer` → `int`, `numeric` → `float`, `boolean` и `in:0,1` →
  `bool`, остальные списки `in:` → `select` с вариантами значений, `field_type: password` →
  `password`; `required`, `min`, `max`, `between` и `regex` становятся правилами проверки (для
  числовых типов `min`/`max` — границы значения, для остальных — ограничения длины).
* В метаданные модификации записываются ключи, которые читают менеджеры процессов Docker и Podman
  демона: `docker_image`, `docker_installation_image`, `docker_installation_script`,
  `docker_installation_entrypoint`, `docker_installation_user: root`,
  `docker_workdir: /home/container`. Ещё два ключа — `docker_startup_done` и `pelican_egg`
  (исходный egg) — хранятся только для справки, демон их не читает. Исходный egg также сохраняется
  в метаданных игры.

### Ограничения

* Переменная без `env_variable` или с именем длиннее 32 символов отбрасывается с предупреждением в
  журнале панели.
* Правило `regex`, которое не компилируется движком RE2 в Go (опережающие и ретроспективные
  проверки PCRE, обратные ссылки), отбрасывается.
* Если переведённая переменная оказывается невалидной, её тип, варианты значений и правила
  отбрасываются; остаются только имя, значение по умолчанию, подпись, признак администратора и
  описание.
* Команда запуска для Windows не создаётся.
* Остальное содержимое egg — `config.files`, `config.stop`, `config.logs`, `features`,
  `file_denylist`, дополнительные Docker-образы, команды запуска кроме `Default` — хранится в
  `pelican_egg` как есть и в настройки панели не переносится.

## Обновление игр из каталога GameAP

Панель поставляется с каталогом готовых настроек игр и модификаций. Чтобы подтянуть из него
изменения, нажмите **Обновить игры** на странице **Администрирование** → **Игры**.

Через API:

```text
POST /api/games/upgrade
```

> **Ваши изменения могут быть перезаписаны.** Если вы правили команды запуска или переменные у
> стандартных игр, сохраните их перед обновлением — например, выгрузив игру в файл через экспорт.

Что обновление делает с существующими данными:

* **Запись игры заменяется** записью из каталога целиком (сопоставление по коду): название,
  движок, Steam App ID, репозитории, метаданные. Поле, которого нет в записи каталога,
  очищается — в том числе локальные репозитории.
* **Модификация сливается** (сопоставление по имени в пределах игры): перезаписываются только те
  локальные поля, которые заполнены у модификации в каталоге — удалённые репозитории, команды
  запуска, команды RCON. Локальные репозитории и метаданные модификации не затрагиваются.
* **Переменные сливаются по имени**, команды Fast RCON — по строке команды. Запись из каталога
  заменяет локальную с тем же именем; добавленные вами переменные и команды сохраняются. Записи
  каталога идут первыми, поэтому порядок на странице настроек следует каталогу.
* Модификация каталога, у которой переменные или команды Fast RCON не проходят проверку,
  пропускается с предупреждением в журнале панели; остальное обновление продолжается.
* Модификация не обновляется, если в панели нашлось несколько модификаций с одним именем для этой
  игры — такие случаи пропускаются, чтобы не перезаписать не ту.

Адреса каталога задаются переменной `GAMES_CDN_URLS`; они перебираются по порядку, пока один
не ответит. См. [Справочник config.env](/ru/config.html).

## Особенности Pelican и Pterodactyl

Импортированные egg работают только с [менеджерами процессов](/ru/daemon/process_managers.html)
Docker и Podman. У игры, созданной импортом, нет ни репозиториев, ни Steam App ID: файлы
устанавливает скрипт установки из egg внутри контейнера по ключам `docker_installation_image` и
`docker_installation_script` из метаданных модификации. С любым другим менеджером процессов
установка завершается ошибкой `could not determine the rules for installing the game`.

Настройте GameAP Daemon на работу с одним из этих менеджеров. При добавлении новой ноды
разверните блок **Дополнительные настройки** и выберите менеджер в поле **Менеджер процессов**.

![Выбор менеджера процессов Docker при добавлении выделенного сервера](/images/ru/gameap_configure/games_import/daemon_process_manager.png)
