## Новый выделенный сервер

В самом начале работы с панелью необходимо добавить выделенный сервер (VDS/VPS, контейнер, физический
сервер), на котором будет работать GameAP Daemon.

Перейдите на страницу **«Администрирование»** → **«Выделенные серверы»** и нажмите кнопку **«Создать»**.
Откроется окно с готовой командой установки — отдельно для Linux и для Windows.

Сертификаты создаёт и передаёт демону сама панель: генерировать и подписывать их вручную не нужно.

Панель формирует команду по адресу из адресной строки браузера (за обратным прокси — из заголовка
`X-Forwarded-Host`), если не задан `GRPC_EXTERNAL_HOST`. Если этот адрес не покрыт gRPC-сертификатом
панели — панель за NAT, за обратным прокси или в Docker, — команда всё равно показывается, но демон,
подключаясь по такому адресу, не пройдёт проверку TLS. Панель записывает предупреждение в свой лог и в
поле `warnings` ответа `GET /api/nodes/setup`; в окне **«Создать»** оно не отображается. gameapctl
проверяет адрес перед установкой — см. [Если установка не удалась](#если-установка-не-удалась) и
[GRPC API](/ru/daemon/grpc.html).

> Ключ установки действует **1 час** и одноразовый — после успешной регистрации демона он гасится.
> Ключ общий для всей панели, поэтому повторное открытие окна «Создать» выпускает новый ключ,
> а ранее скопированная команда перестаёт работать.

### Что нужно на выделенном сервере

* Права суперпользователя (root в Linux, администратор в Windows).
* Исходящий доступ к панели по порту **31718/TCP** — по нему демон общается с панелью по gRPC.
  Это единственный порт панели, который нужен работающему демону.
* Исходящий доступ к `github.com` и `api.github.com` — оттуда скачиваются gameapctl и сам демон.
* Для Linux-скрипта: установленные `curl`, `tar` и `install`.
* Архитектура: `amd64`, `arm64`, `386` или `arm`.

Порт **8025** — это веб-интерфейс и API панели. Он нужен браузеру администратора и команде `curl`
в однострочнике установки, но работающему демону не требуется.

Порт **31717** демон при регистрации указывает как свой собственный. В GameAP 4 панель не устанавливает
входящих соединений к демону, поэтому открывать этот порт на выделенном сервере не требуется.

### Установка на Linux

Скопируйте команду из вкладки Linux и выполните её на выделенном сервере **от имени root**:

```bash
bash <(curl -fsSL 'https://your-panel/nodes/setup/zItWHWlI4RKPl9ZsYc3y3WgdKq7mNvBx')
```

Скрипт проверит окружение, установит `gameapctl` в `/usr/local/bin` (а если он уже установлен —
обновит его), после чего запустит `gameapctl daemon install`. Тот поставит GameAP Daemon, создаст
пользователя `gameap`, установит SteamCMD, зарегистрирует демона в панели и запустит его как сервис
systemd `gameap-daemon`.

Команду нужно запускать именно от root, а не через `sudo`: подстановка процесса `bash <(...)` не
переживает `sudo`, и скрипт остановится с ошибкой. Если вы работаете не из-под root, скачайте скрипт
в файл и запустите его:

```bash
curl -fsSL 'https://your-panel/nodes/setup/zItWHWlI4RKPl9ZsYc3y3WgdKq7mNvBx' -o gameap-setup.sh
sudo bash gameap-setup.sh
```

Куда всё устанавливается:

| Что                | Путь                                    |
|--------------------|-----------------------------------------|
| Демон              | `/usr/bin/gameap-daemon`                |
| Конфигурация       | `/etc/gameap-daemon/gameap-daemon.yaml` |
| Сертификаты        | `/etc/gameap-daemon/certs`              |
| Рабочий каталог    | `/srv/gameap`                           |
| SteamCMD           | `/srv/gameap/steamcmd`                  |
| Логи               | `/var/log/gameap-daemon/output.log`     |

### Установка на Windows

Однострочника для PowerShell нет, установка идёт через gameapctl:

1. Скачайте архив gameapctl для своей архитектуры со страницы
   [релизов gameapctl](https://github.com/gameap/gameapctl/releases). Архив называется
   `gameapctl-<версия>-windows-amd64.zip`.
2. Распакуйте архив и запустите `gameapctl.exe`.
3. В разделе **GameAP Daemon** нажмите **Install**.
4. Вставьте в поле **Connect URL** строку из вкладки Windows в панели.
5. Нажмите **Install**.

То же самое можно сделать командой в консоли:

```shell
gameapctl daemon install --connect=grpc://your-panel:31718/zItWHWlI4RKPl9ZsYc3y3WgdKq7mNvBx
```

Куда всё устанавливается:

| Что                | Путь                                     |
|--------------------|------------------------------------------|
| Демон              | `C:\gameap\daemon\gameap-daemon.exe`     |
| Конфигурация       | `C:\gameap\daemon\gameap-daemon.yaml`    |
| Сертификаты        | `C:\gameap\daemon\certs`                 |
| Рабочий каталог    | `C:\gameap`                              |
| SteamCMD           | `C:\gameap\steamcmd`                     |
| Логи               | `C:\gameap\daemon\logs\output.log`       |

Демон регистрируется как служба **GameAP Daemon**.

### Дополнительные настройки установки

В окне создания есть раскрывающийся блок **«Дополнительные настройки»**:

* **Менеджер процессов** — чем управлять процессами игровых серверов. В Linux доступны `systemd`,
  `docker`, `podman`, `tmux` и `simple`, в Windows — `winsw`, `shawl` и `simple`. По умолчанию
  выбирается автоматически. Подробнее — [Менеджеры процессов](/ru/daemon/process_managers.html).
* **GitHub** — собрать демона из исходников вместо готового релиза.
* **Ветка** — ветка репозитория, если демон собирается из исходников.

Для сборки из исходников на выделенном сервере нужны `git` и Go — gameapctl устанавливает их сам
(Go 1.26.1). GameAP Daemon 4.1.2 объявляет в `go.mod` версию `go 1.26.5`, поэтому `go build`
автоматически загружает нужный toolchain — серверу, помимо `github.com`, нужен исходящий доступ к прокси
модулей Go (`proxy.golang.org`). Для обычной установки оставьте **GitHub** выключенным и используйте
готовую сборку.

Выбранные значения панель дописывает к команде установки:

```bash
bash <(curl -s '...') --config='process_manager.name=docker' --github --branch=master
```

### Ручная установка

Если автоматический скрипт не подходит — нестандартный дистрибутив, свои правила установки пакетов,
установка в подготовленный образ — демона можно зарегистрировать вручную.

1. Скачайте бинарник `gameap-daemon` для своей платформы со страницы
   [релизов демона](https://github.com/gameap/daemon/releases) и разместите его на выделенном сервере.
2. Откройте в панели окно **«Создать»** и возьмите из команды для Windows connect URL вида
   `grpc://хост:порт/ключ`.
3. Выполните регистрацию:

```bash
gameap-daemon enroll --connect=grpc://your-panel:31718/zItWHWlI4RKPl9ZsYc3y3WgdKq7mNvBx
```

Демон подключится к панели, создаст в ней запись о выделенном сервере, получит сертификаты
(`ca.crt`, `server.crt`, `server.key` с правами `0600` в каталоге с правами `0700`) и запишет
файл конфигурации.

| Флаг              | По умолчанию в Linux                    | По умолчанию в Windows                | Назначение                                                              |
|-------------------|-----------------------------------------|---------------------------------------|-------------------------------------------------------------------------|
| `--connect`       | —                                       | —                                     | Connect URL. Обязателен                                                 |
| `--config-path`   | `/etc/gameap-daemon/gameap-daemon.yaml` | `C:\gameap\daemon\gameap-daemon.yaml` | Куда записать конфигурацию                                              |
| `--certs-dir`     | `/etc/gameap-daemon/certs`              | `C:\gameap\daemon\certs`              | Куда сохранить сертификаты                                              |
| `--work-path`     | `/srv/gameap`                           | `C:\gameap`                           | Рабочий каталог игровых серверов                                        |
| `--steamcmd-path` | `/srv/gameap/steamcmd`                  | `C:\gameap\steamcmd`                  | Каталог SteamCMD                                                        |
| `--listen-ip`     | `0.0.0.0`                               | `0.0.0.0`                             | IP, который демон сообщает о себе. При `0.0.0.0` определяется автоматически |
| `--listen-port`   | `31717`                                 | `31717`                               | Порт, который демон сообщает о себе                                     |

> Команда `enroll` перезаписывает файл конфигурации **целиком** — без слияния с существующими
> настройками и без резервной копии. Если демон уже был настроен, сохраните конфигурацию заранее.

После регистрации демона нужно самостоятельно зарегистрировать его как системный сервис и запустить.

### Если установка не удалась

| Сообщение                                                       | Причина                                                                                                                                       |
|-----------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------|
| `This script must be run as root.`                              | Скрипт запущен не от root. Скачайте его в файл и запустите через `sudo`, как показано выше                                                     |
| `Error: 'curl' is required but not installed.`                  | На сервере нет `curl`, `tar` или `install`. Установите недостающий пакет и повторите                                                           |
| `Unsupported architecture: ...`                                 | Для архитектуры сервера нет готовых сборок                                                                                                     |
| `Failed to detect latest gameapctl version`                     | Нет доступа к `api.github.com` либо исчерпан лимит GitHub API (60 запросов в час с одного адреса). Подождите или установите gameapctl вручную   |
| `cannot reach gRPC server at ...`                               | С выделенного сервера не открывается порт 31718 панели. Проверьте файрвол и адрес панели — см. [GRPC API](/ru/daemon/grpc.html)                |
| `WARNING: the panel gRPC certificate does not cover host "..."` | Адрес из команды не входит в gRPC-сертификат панели, но gameapctl нашёл другой адрес той же панели, покрытый сертификатом, и зарегистрировал демона через него (`using ... instead`). Демон работает, но подключается не к тому адресу, который выдала панель. Чтобы сохранить исходный адрес, задайте `GRPC_EXTERNAL_HOST` в конфигурации панели и перезапустите её — gRPC-сертификат перевыпускается автоматически |
| `host "..." is not in the panel gRPC certificate ...`           | Адрес не покрыт сертификатом, и рабочей альтернативы не нашлось (`no working alternative address was found`); установка прерывается. Задайте `GRPC_EXTERNAL_HOST`, перезапустите панель и скопируйте новую команду из окна **«Создать»** — см. [GRPC API](/ru/daemon/grpc.html) |
| Ссылка отдаёт `403`                                             | Ключ установки истёк или был перевыпущен. Откройте окно «Создать» заново и скопируйте новую команду                                            |

## Редактирование выделенных серверов

Страница **«Администрирование»** → **«Выделенные серверы»** показывает выделенные серверы (ноды) в виде
карточек. В панели инструментов три кнопки: **«Создать»**, **«Задания GDaemon»** и **«Клиентские
сертификаты»**. Начиная с 4.5.0 список заданий GDaemon открывается отсюда — отдельного пункта в боковом
меню больше нет.

![Страница «Выделенные серверы» с кнопками «Создать», «Задания GDaemon» и «Клиентские сертификаты» над карточками узлов](/images/ru/gameap_configure/dedicated_servers/nodes_toolbar.png)

На карточке — имя, статус **«Онлайн»**/**«Оффлайн»**, локация, провайдер, первый IP-адрес, версия
демона, а для узла в сети — загрузка процессора, памяти и сети. По клику на карточку открывается окно
сведений с вкладками **«Обзор»** и **«Метрики»** и кнопками **«Редактировать»**, **«Задания GDaemon»**
(список заданий с фильтром по этому узлу, `?node=<id>`), **«Скачать сертификаты»** и **«Удалить»**.

Форма редактирования состоит из четырёх вкладок: **«Основное»**, **«Daemon»**, **«Скрипты»** и
**«Метаданные»**.

### Версия демона

На карточке отображается версия, которую сообщил демон. Если она старше последнего стабильного релиза
GameAP Daemon, карточка показывает `версия → последняя`, где новая версия — оранжевая ссылка на релиз.
На вкладке **«Обзор»** окна сведений выводится **«Версия GameAP Daemon»** с датой сборки; для
устаревшего демона показывается баннер **«Доступна новая версия GameAP Daemon»** со ссылкой на релиз,
для актуального — зелёная галочка с подсказкой **«GameAP Daemon актуален»**.

![Вкладка «Обзор» в окне сведений об узле: рядом с версией GameAP Daemon стоит зелёная галочка](/images/ru/gameap_configure/dedicated_servers/node_overview.png)

Отметка не показывается для узлов не в сети, при отключённой проверке обновлений
(`UPDATE_CHECK_ENABLED=false`, см. [Конфигурация](/ru/config.html)) и если последний релиз определить
не удалось; сборки демона для разработки не получают ни одной из отметок. Обновляется демон командой
`gameapctl daemon upgrade` — см. [GameAP Daemon](/ru/daemon/daemon.html).

Данные берутся из `GET /api/dedicated_servers/summary` (псевдоним `GET /api/nodes/summary`, только для
администраторов). Ответ содержит счётчики `total`, `enabled`, `disabled`, `online`, `offline` и массивы
`onlineNodes` и `offlineNodes`; у каждого элемента есть `id`, `name`, `location`, `enabled` и `online`,
а у элементов массива `onlineNodes` — ещё `version` и `buildDate`. Флаг `outdated` появляется только у
узлов в сети, демон которых старше последнего стабильного релиза.

### Описание параметров

#### Основное

Вкладка содержит карточки **«Основное»** и **«Список IP»**.

##### Имя

Имя выделенного сервера, до 128 символов. Может быть любым непустым значением, ни на какой функционал
не влияет.

##### Включен

Переключатель, который помечает выделенный сервер как включённый или отключённый.

##### Операционная система

`Linux` или `Windows`. Обязательное поле: API принимает только `linux` и `windows`. Пункт **MacOS** есть
в списке, но выбрать его нельзя.

##### Локация

Физическое расположение сервера. Обязательное поле, до 128 символов. Показывается на карточке и на
вкладке **«Обзор»**.

##### Провайдер

Хостинг-провайдер. Необязательное поле, до 128 символов.

##### Рабочий каталог

В этом каталоге располагаются основные скрипты управления процессами игровых серверов. В подкаталогах
рабочего каталога размещаются файлы игровых серверов. Относительно указанного пути назначается 
[каталог игрового сервера](/ru/gameap_configure/game_servers.html#каталог). По умолчанию `/srv/gameap`.

##### Путь к SteamCMD

Путь к каталогу где размещается SteamCMD (там находится скрипт `steamcmd.sh`). По умолчанию `/srv/gameap/steamcmd`.

##### Список IP

Список IP-адресов или хостов, на которых будут работать игровые серверы. Нужен хотя бы один адрес.

#### Скрипты

Шаблоны команд, которыми панель управляет игровыми серверами на этом выделенном сервере. Заполнять не
обязательно: если поле пустое, используется команда по умолчанию.

#### Метаданные

Произвольные пары «ключ — значение», привязанные к выделенному серверу. Предназначены в первую очередь
для плагинов — например, чтобы связать узел с облачным инстансом, на котором он работает
(`hetzner.server_id`). Ограничения: не более 512 ключей, ключ — до 255 символов, значение — до 16 КиБ в
сериализованном виде.

![Вкладка «Метаданные» в форме редактирования выделенного сервера с ключом datacenter и его значением](/images/ru/gameap_configure/dedicated_servers/node_metadata.png)

> Метаданные доступны на чтение всем плагинам, поэтому не храните в них секреты и учётные данные.

Через API (`PUT /api/nodes/{id}`): если поле `metadata` не передано, сохранённые пары остаются; объект
полностью заменяет их; пустой объект `{}` очищает их (`null` не принимается). Плагины меняют метаданные
через [API плагинов](/ru/plugins/development.html): переданные ключи объединяются с существующими, а
`remove_metadata_keys` удаляет перечисленные ключи.

#### Daemon

Данные о подключении демона. Заполняются автоматически при регистрации выделенного сервера, менять их
вручную обычно не требуется.

В GameAP 4 соединение устанавливает демон: он сам подключается к панели по gRPC и держит постоянное
соединение. Панель к демону не подключается.

##### GameAP Daemon хост и порт

Адрес и порт, которые демон сообщил о себе при регистрации. Порт принимает значения от `1` до `65535`,
по умолчанию `31717`. Значения носят справочный характер — панель их для подключения не использует,
открывать этот порт на выделенном сервере не требуется.

На панелях с PostgreSQL до версии 4.4.1 включительно колонка порта имела тип `SMALLINT`, и значения
выше 32767 отклонялись базой данных; начиная с 4.4.2 принимается весь диапазон.

##### GameAP Daemon логин и пароль

Устаревшие поля из GameAP 3, где панель подключалась к демону сама. В GameAP 4 не используются,
заполнять их не нужно.
