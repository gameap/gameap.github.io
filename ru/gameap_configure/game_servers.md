## Страница игрового сервера

Откройте **Список серверов** и выберите сервер. Страница разделена на вкладки; их набор зависит
от того, какие права выданы пользователю, и от возможностей игры.

| Вкладка               | Что на ней                                                                  |
|-----------------------|------------------------------------------------------------------------------|
| **Управление**        | Кнопки запуска, остановки, перезапуска, обновления и переустановки, состояние сервера, консоль и статистика |
| **RCON**              | Консоль RCON и управление игроками. Появляется, если игра поддерживает RCON   |
| **Файлы**             | Файловый менеджер сервера                                                    |
| **Планировщик задач** | Периодические задачи: перезапуск, обновление, произвольные команды             |
| **Настройки**         | Значения переменных модификации для этого сервера                             |

Плагины могут добавлять к серверу собственные вкладки — они появляются рядом со штатными.

### Управление

Основная вкладка. Кроме кнопок управления на ней:

**Состояние сервера** — работает или остановлен, текущая карта и количество игроков, если игра
отдаёт эти данные по протоколу Query.

**Консоль** — вывод игрового сервера и поле для отправки команд. Работает не через RCON,
а через менеджер процессов на выделенном сервере, поэтому доступна и тогда, когда сервер ещё
не успел подняться.

**Статистика** — графики загрузки процессора, памяти и сети. Данные собирает демон с периодом
`metrics.collection_interval` (по умолчанию 5 секунд) и хранит `metrics.retention_duration`
(по умолчанию 10 минут), см. [GameAP Daemon](/ru/daemon/daemon.html#сбор-метрик).

### Файлы

Файловый менеджер работает в каталоге игрового сервера. Позволяет просматривать и редактировать
файлы, загружать и скачивать их, создавать каталоги, менять права доступа.

Загрузка проверяется по типу файла: тип определяется по содержимому, а не по расширению.
Разрешить загрузку архивов и двоичных файлов можно переменными `FILES_UPLOAD_ALLOW_ARCHIVES`
и `FILES_UPLOAD_ALLOW_BINARY`, см. [Безопасность](/ru/security.html).

### Планировщик задач

Периодические задачи для сервера: перезапуск по расписанию, обновление, выполнение команды.
Задачи выполняет демон на выделенном сервере.

### Настройки

Значения переменных, объявленных в модификации игры, — например карта по умолчанию или число
слотов. Они подставляются в команду запуска вместо шорткодов. Какие переменные доступны, задаётся
[в настройках модификации](/ru/gameap_configure/games.html#переменные).

Каждая переменная отображается элементом формы, который соответствует её типу:

| Тип        | Элемент формы                                                                                   |
|------------|-------------------------------------------------------------------------------------------------|
| `string`   | Однострочное текстовое поле                                                                     |
| `text`     | Многострочное текстовое поле                                                                    |
| `int`      | Целочисленное поле со степпером, ограниченное `min` и `max` переменной                          |
| `float`    | Числовое поле, ограниченное `min` и `max`                                                       |
| `bool`     | Переключатель                                                                                   |
| `select`   | Выпадающий список с поиском. Если переменная допускает произвольные значения, можно ввести своё |
| `password` | Поле с маскированием; значение можно показать по клику                                          |

![Вкладка «Настройки» игрового сервера со встроенными переключателями и переменными модификации с пометкой «Только для администраторов»](/images/ru/gameap_configure/games/server_settings_widgets.png)

Значение по умолчанию показывается как подсказка в пустом поле, описание переменной — под полем.
Значения проверяются в браузере и повторно панелью при сохранении. Если хотя бы одно значение
нарушает правила, ничего не записывается: поля с ошибками подсвечиваются вместе с текстом
ошибки, а панель выводит сообщение **«Проверьте выделенные поля.»**

Переменная с признаком **«Переменная администратора»** в модификации показывается администраторам
с бейджем **«Только для администраторов»**, а остальным пользователям не видна вовсе.

На вкладке всегда есть две встроенные настройки. Они принадлежат панели, а не модификации:

| Настройка                             | Ключ                  |
|---------------------------------------|-----------------------|
| **«Автозапуск в случае падения»**     | `autostart`           |
| **«Обновлять сервер перед запуском»** | `update_before_start` |

## Редактирование игровых серверов

Для редактирования игрового сервера перейдите на страницу **"Администрирование"** → **"Игровые серверы"**, затем 
выберите игровой сервер, который хотите отредактировать и нажмите на кнопку **"Редактировать"**.

### Описание параметров

#### Основное

Основная группа параметров

##### UUID

UUID — универсальный уникальный идентификатор. Для каждого сервера он генерируется автоматически. Он используется как 
идентификатор для процессов игровых серверов.

##### Имя

Название сервера. Может быть любым строковым значением. Название игровому серверу можно придумать любое.

##### Игра

Игра, к которой принадлежит игровой сервер. Документацию по настройке игр читайте в соответсвующем разделе — 
[Настройка игр](/ru/gameap_configure/games.html).

Читайте также [Мануал по добавлению отсутствующих игр](/ru/tutorials/additional_games.html).

##### Модификация

Модификация, к которой принадлежит игровой сервер. Модификацию может определять дополнительные настройки (переменные) 
для игрового сервера, такие как карта по умолчанию (`{default_map}`), FPS и другие. Информацию о том, как
добавить свои настройки и другую подробную информацию об этом читайте на странице 
[настройки игр](/ru/gameap_configure/games.html#переменные), в соответствующем разделе.

##### RCON пароль

Пароль для управления игровым сервером через RCON.

##### Каталог

Каталог игрового сервера относительно [рабочего каталога выделенного сервера](/ru/gameap_configure/dedicated_servers.html#рабочий-каталог).

Например, если каталог указан как `servers/my_server`, а рабочий каталог выделенного сервера `/srv/gameap`, то игровой
сервер будет расположен в каталоге `/srv/gameap/servers/my_server`.

##### Имя пользователя на выделенном сервере

Пользователь, от которого будет запускаться игровой сервер на ноде. По умолчанию `gameap`.

Пользователь, который указан в этом поле, должен обязательно присутствовать на выделенном сервере.

#### Выделенный сервер, IP, порты

Группа параметров, которая относится к выделенному серверу (VDS, ноде) и подключению к игровому серверу.

##### Выделенный сервер

Нода, на которой работает игровой сервер. Выбирается при создании сервера; в форме редактирования
поле отображается, но изменить его нельзя.

##### IP

IP или Хост игрового сервера. Примеры `127.0.0.1`, `my-server.gameap.ru`. По этому адресу
подключается демон. Чтобы показывать пользователям другой адрес — например, когда нода за NAT, —
задайте ключ `public_ip` в разделе [Метаданные](#метаданные).

##### Порт сервера

Основной порт сервера. Используется для подключения игроков к серверу.

##### Query порт

Порт сервера для запросов. Query используется для получение общих данных о сервере: текущая карта, текущее количество 
игроков на сервере, список игроков.

В GoldSource и Source совпадает с основным портом сервера. В Minecraft можно указать любой порт. В некоторых
других игровых серверах может быть на единицу больше или меньше.

##### RCON порт

Порт сервера для удалённого управления.

В GoldSource и Source совпадает с основным портом сервера. В Minecraft можно указать любой порт. В некоторых
других игровых серверах может быть на единицу больше или меньше.

Порт сервера, Query-порт и RCON-порт принимают любое значение от 1 до 65535. Панель проверяет
только диапазон; сами порты должны быть открыты на выделенном сервере.

> До версии 4.4.1 включительно панель на PostgreSQL хранила порты в колонках `SMALLINT` и
> отклоняла значения больше 32767 с ошибкой базы данных. Начиная с 4.4.2 колонки имеют тип
> `INTEGER`, и полный диапазон работает одинаково на PostgreSQL, MySQL/MariaDB и SQLite.

#### Лимиты ресурсов

Ограничения на потребление ресурсов игровым сервером.

##### Лимит CPU

Задаётся в миллиядрах: `1000` — одно полное ядро, `500` — половина ядра. В интерфейсе значение
можно вводить также в процентах или в ядрах, панель пересчитает его сама.

##### Лимит RAM

Предельный объём оперативной памяти. В интерфейсе вводится в байтах, мегабайтах или гигабайтах.

> Лимиты применяются только теми менеджерами процессов, которые это умеют: **systemd**, **Docker**
> и **Podman**. При работе через `tmux`, `winsw`, `shawl` или `simple` заданные значения ни на что
> не влияют. См. [Менеджеры процессов](/ru/daemon/process_managers.html).

Пустое или нулевое значение означает отсутствие ограничения.

#### Команда запуска

Команда запуска — важный и обязательный параметр для запуска игрового сервера. Представляет из себя строку с различными
опциями и параметрами запуска игрового сервера. Для каждой игры и модификации может быть индивидуальным.

В параметрах могут присутствовать шорткоды, которые автоматически заменяются на значение настроек (переменных)
конкретного игрового сервера. Шорткоды представляют из себя слова в фигурных скобках `{` и `}`, например `{ip}`, 
`{port}`, `{default_map}` и другие. 

О том, как добавить свои собственные шорткоды, которые будут автоматически заменяться на значение настроек читайте на
странице [настройки игр](/ru/gameap_configure/games.html#переменные).

#### Метаданные

Произвольные пары «ключ — значение», хранящиеся вместе с сервером. В карточке **«Метаданные»**
есть справочник известных ключей с примерами. Ключи делятся на две группы.

**Ключи панели.** Зарезервированный ключ `public_ip` переопределяет адрес, который показывается
для сервера. Если он задан, в списке серверов и на странице сервера все пользователи, включая
администраторов, видят это значение, а демон продолжает подключаться по адресу из поля **«IP»**
(API возвращает его как `internal_server_ip`). Ключ нужен для выделенных серверов за NAT, чей
адрес в локальной сети не должен быть виден. Значение — только IP-адрес или имя хоста; значение
с портом отклоняется с ошибкой `metadata.public_ip is not a valid IP address or hostname`.
Пустое значение снимает переопределение.

**Ключи контейнеров.** Ключи `docker_*` (`docker_image`, `docker_workdir`,
`docker_installation_script` и другие) читают менеджеры процессов Docker и Podman на демоне,
см. [Менеджеры процессов](/ru/daemon/process_managers.html#docker).

## Отправка команд в консоль

Команда, введённая в консоли на вкладке «Управление», передаётся игровому серверу одним из двух
способов.

Если у выделенного сервера задан шаблон **«Команда отправки команды в консоль»**
(`script_send_command`), панель подставляет в него команду и выполняет на выделенном сервере.
Если шаблон не задан, команда записывается во входной файл игрового сервера.

> **Не заключайте `{command}` в кавычки.** Панель подставляет значение уже в кавычках: перед
> подстановкой команда экранируется для оболочки и оборачивается в одинарные кавычки. Если
> добавить свои, получится двойное экранирование, и сервер получит команду вместе с кавычками.

Правильно:

```text
tmux send-keys -t {uuid} {command} Enter
```

Неправильно:

```text
tmux send-keys -t {uuid} "{command}" Enter
```

Шаблон задаётся на странице **«Администрирование»** → **«Выделенные серверы»** → выберите сервер →
**«Редактировать»** → вкладка **«Скрипты»**.
