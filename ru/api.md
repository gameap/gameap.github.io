Панель полностью управляется через HTTP API — интерфейс работает через тот же API. Полное описание
методов со схемами запросов и ответов доступно на [openapi.gameap.io](https://openapi.gameap.io/).

Эта страница — о том, как в API аутентифицироваться.

## Способы аутентификации

| Способ                          | Для чего                                            | Срок жизни          |
|---------------------------------|------------------------------------------------------|---------------------|
| Токен сессии                    | Работа интерфейса                                    | 24 часа или 7 дней  |
| Персональный токен доступа (PAT)| Скрипты, интеграции, автоматизация                   | Бессрочно           |
| Короткоживущий токен            | WebSocket и скачивание файлов                        | 10 секунд           |

Токен передаётся заголовком:

```http
Authorization: Bearer <токен>
```

Внешняя система может также выполнить вход пользователя без пароля — по одноразовому
[билету SSO](#билеты-входа-sso). Сам билет не является bearer-токеном: он обменивается
на обычный токен сессии.

## Персональные токены доступа

Это основной способ для автоматизации: токен не привязан к сессии, не истекает и имеет собственный
набор разрешений.

### Создание

Создать токен можно на странице **Токены** (меню пользователя в верхней панели) или запросом:

```bash
curl -X POST https://panel.example.com:8025/api/tokens \
  -H "Authorization: Bearer <токен сессии>" \
  -H "Content-Type: application/json" \
  -d '{"token_name": "ci-deploy", "abilities": ["server:list", "server:restart"]}'
```

| Поле         | Ограничения                                                            |
|--------------|------------------------------------------------------------------------|
| `token_name` | Обязательное; до 255 символов                                          |
| `abilities`  | Обязательное; от 1 до 100 разрешений из списка ниже, без повторов      |

Создать токен можно только из сессии: запрос, аутентифицированный персональным токеном,
отклоняется с кодом `403`. Разрешения с префиксом `admin:` может запросить только администратор —
у любого другого пользователя запрос не пройдёт проверку.

Ответ содержит токен целиком:

```json
{"token": "12|kJ3n8sQm..."}
```

> Токен показывается **только один раз**. В базе хранится лишь его хеш SHA-256, восстановить
> значение невозможно — если потеряли, выпустите новый.

Формат токена — `{идентификатор}|{секрет}`. Разделитель `|` обязателен: передавайте значение
целиком, как оно выдано.

### Разрешения токена

Разрешения указываются при создании и ограничивают токен независимо от прав пользователя: токен
не может больше, чем разрешено ему, и не может больше, чем разрешено его владельцу.

| Разрешение                | Что позволяет                                                              |
|---------------------------|----------------------------------------------------------------------------|
| `server:list`             | Просмотр списка серверов                                                   |
| `server:start`            | Запуск сервера                                                             |
| `server:stop`             | Остановка сервера                                                          |
| `server:restart`          | Перезапуск сервера                                                         |
| `server:update`           | Обновление сервера                                                         |
| `server:console`          | Чтение и запись в консоль                                                  |
| `server:rcon-console`     | Консоль RCON                                                               |
| `server:rcon-players`     | Управление игроками через RCON                                             |
| `server:tasks-manage`     | Управление задачами сервера                                                |
| `server:settings-manage`  | Управление настройками сервера                                             |
| `admin:server:create`     | Создание серверов                                                          |
| `admin:gdaemon-task:read` | Чтение заданий демона                                                      |
| `admin:user:read`         | Чтение пользователей и назначенных им серверов                             |
| `admin:user:manage`       | Создание и изменение пользователей, назначение серверов и прав на серверы  |
| `admin:node:read`         | Чтение узлов, их IP-адресов и занятых портов                               |
| `admin:game:read`         | Чтение игр и модификаций                                                   |
| `admin:user:sso`          | Выпуск билетов входа SSO для других пользователей                          |

Разрешения с префиксом `admin:` может выдать только администратор — при попытке добавить их
обычным пользователем запрос завершится ошибкой.

Эндпоинты объявляют требуемые разрешения; если эндпоинт объявляет несколько, токен должен
иметь все. Токен без нужного разрешения получает `403`. Административные
эндпоинты открыты персональному токену только тогда, когда объявляют разрешение:

| Разрешение                | Эндпоинты                                                                                                                                                               |
|---------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `admin:server:create`     | `POST /api/servers`, `PUT` и `DELETE /api/servers/{id}`                                                                                                                 |
| `admin:gdaemon-task:read` | `GET /api/gdaemon_tasks/{id}`                                                                                                                                           |
| `admin:user:read`         | `GET /api/users`, `GET /api/users/{id}`, `GET /api/users/{id}/servers`, `GET /api/users/{id}/servers/{server}/permissions`                                              |
| `admin:user:manage`       | `POST /api/users`, `PUT /api/users/{id}`, `PUT /api/users/{id}/servers/{server}/permissions`, `PUT` и `DELETE /api/users/{id}/servers/{server}`                         |
| `admin:node:read`         | `GET /api/nodes`, `GET /api/nodes/{id}`, `GET /api/nodes/{node}/busy_ports`, `GET /api/nodes/{node}/ip_list`                                                            |
| `admin:game:read`         | `GET /api/games`, `GET /api/games/{code}`, `GET /api/games/{code}/mods`, `GET /api/game_mods`, `GET /api/game_mods/{id}`, `GET /api/game_mods/get_list_for_game/{game}` |
| `admin:user:sso`          | `POST /api/auth/sso/tickets`                                                                                                                                            |

Все остальные административные эндпоинты — удаление пользователей, создание и изменение узлов,
игр и модификаций, управление плагинами, `GET /api/version` — закрыты для персональных токенов
независимо от их разрешений: ответ — `403` «personal access tokens cannot access this
administrative endpoint».

Независимо от разрешений персональный токен также не может (`403`):

- назначить административную роль при создании или изменении пользователя;
- изменить пользователя-администратора, в том числе назначить или отвязать ему серверы;
- сменить пароль пользователя через `PUT /api/users/{id}`;
- управлять двухфакторной аутентификацией — настройкой, подтверждением, отключением, кодами
  восстановления;
- создать другой токен.

Обоснование этих ограничений — в разделе [Безопасность](/ru/security.html).

Актуальный список разрешений доступен запросом:

```http
GET /api/tokens/abilities
```

Ответ сгруппирован (`server`, `gdaemon-task`, `user`, `node`, `game`). Разрешения `admin:` и их
группы возвращаются только администраторам.

### Просмотр и отзыв

```http
GET    /api/tokens        — список своих токенов
DELETE /api/tokens/{id}   — отозвать токен
```

В списке видны имя, разрешения и время последнего использования — по нему удобно находить
неиспользуемые токены.

> **Смена пароля отзывает токены.** Все персональные токены, созданные до смены пароля, перестают
> работать. После смены пароля выпустите токены заново.

### Пример использования

```bash
TOKEN='12|kJ3n8sQm...'

# список серверов
curl -H "Authorization: Bearer $TOKEN" \
  https://panel.example.com:8025/api/servers

# перезапуск сервера
curl -X POST -H "Authorization: Bearer $TOKEN" \
  https://panel.example.com:8025/api/servers/1/restart
```

## Токен сессии

Выдаётся при входе по логину и паролю:

```bash
curl -X POST https://panel.example.com:8025/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"login": "admin", "password": "..."}'
```

Формат токена — PASETO v4.local. Обычная сессия живёт 24 часа, с отметкой «запомнить меня» — 7 дней.
Выход (`POST /api/auth/logout`) заносит токен в список отозванных, который проверяется при каждом
запросе.

Если у пользователя включена двухфакторная аутентификация, вход возвращает не токен, а
`two_factor_required` вместе с `challenge_token`; второй фактор подтверждается запросом
`POST /api/auth/2fa/verify`. Подробности — [Безопасность](/ru/security.html).

Для автоматизации сессионные токены неудобны: они истекают, а вход защищён ограничением частоты
попыток и, возможно, капчей. Используйте персональные токены.

## Короткоживущие токены

Нужны там, где токен вынужден передаваться в адресе страницы — подключение по WebSocket и скачивание
файлов. Выдаются запросом `POST /api/auth/short-lived-token`, имеют префикс `glst_`, одноразовые
и живут не дольше 10 секунд независимо от настроек.

Только такие токены принимаются в параметре запроса `?token=`; персональный токен там передать
нельзя — это защищает его от попадания в журналы веб-серверов и историю браузера.

## Билеты входа SSO

Одноразовый билет позволяет внешней системе, которая уже знает пользователя — например биллингу
с кнопкой «открыть игровую панель», — выполнить вход этого пользователя в GameAP без пароля.
Интерфейса для выпуска билетов нет: сценарий доступен только через API.

**1. Выпустите билет** запросом `POST /api/auth/sso/tickets` — с токеном сессии администратора
или с персональным токеном, имеющим разрешение `admin:user:sso`:

```bash
curl -X POST https://panel.example.com:8025/api/auth/sso/tickets \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"user_id": 42, "redirect_to": "/servers/6"}'
```

| Поле          | Назначение                                                                                                                                                                                                             |
|---------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `user_id`     | Обязательное. Пользователь, которого билет вводит в панель                                                                                                                                                             |
| `redirect_to` | Необязательное. Путь внутри панели, который откроется после входа; должен быть относительным и начинаться с `/`, иначе `422`                                                                                           |
| `client_ip`   | Необязательное. Привязывает билет к IP-адресу браузера — обмен с любого другого адреса отклоняется. Должен быть буквальным IPv4- или IPv6-адресом; имеет смысл только за прокси с настроенным `AUDIT_CLIENT_IP_HEADER` |

Ответ:

```json
{"ticket": "glsso_aB3dE5fG7hJ9kL1mN3pQ5rS7tU9vW1xY3zA5bC7dE9f", "expires_in": 60, "redirect_to": "/servers/6"}
```

Билет имеет префикс `glsso_`, одноразовый и живёт `AUTH_SSO_TICKET_TTL` (по умолчанию 60 секунд,
не более 120). Билет для администратора выпускается только для той учётной записи, от имени
которой аутентифицирован сам запрос; для любого другого администратора ответ — `403`. Неизвестный
`user_id` возвращает `404`.

**2. Передайте билет в браузер** во фрагменте URL:

```
https://panel.example.com:8025/sso#t=<билет>
```

Фрагмент не отправляется на сервер, поэтому билет не попадает в журналы веб-сервера и прокси.
Страница `/sso` считывает его и выполняет обмен самостоятельно.

**3. Обмен** — `POST /api/auth/sso/exchange` с телом `{"ticket": "glsso_..."}`, без
аутентификации. Билет изымается атомарно, поэтому повторный запрос проигрывает. Ответ такой же,
как при входе по паролю:

- обычная сессия — `token`, `expires_in`, `user`, `redirect_to`;
- при включённой двухфакторной аутентификации — `two_factor_required: true` и `challenge_token`;
  завершите вход запросом `POST /api/auth/2fa/verify`. SSO не обходит второй фактор;
- для администратора без второго фактора — действует та же политика MFA для администраторов, что
  и при входе по паролю: `mfa_nudge` в льготный период, затем `mfa_enrollment_required: true`
  с токеном, ограниченным эндпоинтами настройки 2FA.

Недействительный, истёкший, уже использованный или не совпавший по IP-адресу билет отклоняется
с кодом `401` — как и билет для учётной записи, которая оказалась администратором, отличным
от выпустившего билет (например, повышенным после выпуска). Неудачные обмены ограничиваются
по частоте на адрес отдельным счётчиком — 60 за 15 минут.

Везде, кроме эндпоинта обмена, билет бесполезен: переданный в заголовке `Authorization`,
в строке запроса или в cookie, он отклоняется с кодом `401`.

> За балансировщиком билет может быть выпущен на одном экземпляре панели, а обменян на другом —
> требуется общий кэш (`CACHE_DRIVER=redis` или `postgres`).
> См. [Несколько экземпляров панели](/ru/multi_instance.html).

Модель угроз и ограничения для администраторов описаны в разделе
[Безопасность](/ru/security.html).

## Эндпоинт версии

`GET /api/version` возвращает версию работающей панели и, если проверка обновлений включена,
последние доступные релизы панели и GameAP Daemon. Только для администраторов и только с токеном
сессии: разрешения для этого эндпоинта не существует, поэтому персональный токен отклоняется
с кодом `403`.

```json
{
  "panel": {
    "current": "4.4.1",
    "build_date": "2026-08-06T14:42:13Z",
    "is_release": true,
    "latest_stable": "4.4.2",
    "latest_stable_url": "https://github.com/gameap/gameap/releases/tag/v4.4.2",
    "update_available": true
  },
  "daemon": {
    "latest_stable": "4.1.2",
    "latest_stable_url": "https://github.com/gameap/daemon/releases/tag/v4.1.2"
  },
  "update_check_enabled": true
}
```

| Поле                                               | Назначение                                                                                                                          |
|----------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------|
| `panel.current`, `panel.build_date`                | Версия и дата сборки работающей панели                                                                                              |
| `panel.is_release`                                 | `false` для сборок разработки, версия которых не является корректной семантической версией; такие сборки с релизами не сравниваются |
| `panel.latest_stable`, `panel.latest_stable_url`   | Последний стабильный релиз и страница релиза                                                                                        |
| `panel.latest_beta`, `panel.latest_beta_url`       | Последний предрелиз; присутствует, только если новее последнего стабильного                                                         |
| `panel.update_available`                           | Новее ли последний стабильный релиз работающей версии                                                                               |
| `daemon.latest_stable`, `daemon.latest_stable_url` | Последний стабильный релиз GameAP Daemon и страница релиза                                                                          |
| `daemon.latest_beta`, `daemon.latest_beta_url`     | Последний предрелиз GameAP Daemon; присутствует, только если новее стабильного                                                      |
| `update_check_enabled`                             | Разрешено ли панели проверять наличие новых релизов                                                                                 |

Сетевые ошибки никогда не приводят к ошибке запроса: если источник релизов недоступен или проверка
обновлений отключена, поля `latest_*` просто отсутствуют. Проверка обновлений настраивается
переменными `UPDATE_CHECK_*` — см. [Справочник config.env](/ru/config.html).

## Ограничения и коды ответов

| Код   | Значение                                                                                    |
|-------|---------------------------------------------------------------------------------------------|
| `204` | Успех без тела ответа — например, отзыв токена, назначение или отвязка сервера пользователю |
| `400` | Некорректное тело запроса                                                                   |
| `401` | Токен не передан, недействителен или отозван; недействительный или истёкший билет SSO       |
| `403` | Токену или пользователю не хватает прав                                                     |
| `404` | Объект не найден                                                                            |
| `409` | Конфликт — например, пользователь с таким логином или e-mail уже существует                 |
| `422` | Ошибка проверки данных запроса                                                              |
| `429` | Превышен предел попыток — вход, проверка второго фактора, обмен билета SSO                  |

Ограничение частоты действует на вход и проверку второго фактора — 20 неудачных попыток с одного
адреса и 5 на один логин за 15 минут — и на обмен билета SSO, у которого отдельный счётчик:
60 неудачных попыток с одного адреса за 15 минут. На запросы с персональным токеном ограничений
по частоте нет.

## CORS

Если API вызывается из браузера со стороннего адреса, перечислите допустимые источники
в `HTTP_ALLOWED_ORIGINS` — полностью, со схемой. Подстановка `*` не поддерживается.
См. [Справочник config.env](/ru/config.html).
